# 에듀테크 오라클

**[근거 위키 열람 → taehyeonglim.github.io/edtech-oracle](https://taehyeonglim.github.io/edtech-oracle/)**

에듀테크에 관해 물으면 **교육공학의 위인 36인이 등장해 학술적 근거를 인용하며** 답한다. 한 명이 답하기도 하고 여러 명이 갈리기도 하며, 서로 토론하기도 한다.

선행 프로젝트 [edtech-pantheon](https://github.com/taehyeonglim/edtech-pantheon)이 교육공학을 **읽는** 아카이브라면, 오라클은 같은 근거로 **말하는** 시스템이다.

> **현재 상태 — 동작하며, 형식적 무결성은 기계가 지킨다**
>
> 위인 36인의 근거 위키와 서브에이전트가 동작하고, 근거를 따라갈 수 있는 [열람 사이트](#열람-사이트)가 있다.
> 디스코드 봇([`bot/`](bot/))은 `/ask`·`/debate` 3라운드까지 실전 검증을 마쳤다.
> 2026-08-20에 [성능 프로브 85건](#측정--무엇이-검증되었나)을 돌려 **위조급 0 · 환각 0 · 위인 격리 100%**를 확인했다.
> 위인 33인의 비판·한계 서술은 `gpt-5.6-luna`가 생성했으며, 2026-08-14에 33인 전수 감사를 마쳐
> 귀속 오류는 발견되지 않았다.
>
> **검증되지 않은 것이 더 중요하다.** "이 각주가 이 문장의 근거가 맞는가"는 기계가 판정하지 않는다.
> [알려진 이슈](#알려진-이슈)를 함께 읽기 바란다.

## 무엇이 다른가

이 프로젝트의 제약은 하나다 — **모든 말에 근거를 인용한다.**

그래서 위인들은 세 가지 마커 중 하나를 달고 말한다.

```
[근거]     내 문헌에 직접 있는 주장. 각주 필수
[적용]     내 원리를 현대 상황에 적용한 추론. 출발 원리의 각주 + 추론임을 명시
[근거없음] 내 문헌에 근거가 없다. 지어내지 않는다
```

`[적용]`이 필요한 이유는 시대 격차다. 사용자 질문은 대부분 생성형 AI·LMS·마이크로러닝인데 위인들은 1900~2000년대 인물이다. 마커가 없으면 "가네가 AI 튜터에 대해 이렇게 말했다"는 문장이 근거 있는 주장처럼 유통된다.

`[근거없음]`은 회피가 아니라 정직성 장치다. 이게 없으면 위인들은 그럴듯하게 지어낸다.

## 구조

Karpathy의 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 패턴을 따른다 — 3계층과 3오퍼레이션만 고정이고 스키마는 도메인에 맞게 설계했다.

```
raw/          Layer 1 · 불변 원자료 (gitignore, 목록만 MANIFEST.md로 공개)
wiki/         Layer 2 · 에이전트가 유지하는 마크다운
CLAUDE.md     Layer 3 · 스키마 정본
```

```
wiki/
├── index.md · log.md · router-map.md · KNOWN-ISSUES.md   type: meta
├── pioneers/   36   위인의 정체성과 자기 입장
├── debates/    34   대립축 (Clark–Kozma 매체 효과 논쟁 등)
├── concepts/    6   개념 정본 — `npm run concepts:candidates`가 후보를 낸다
└── sources/   140   출처 요약
```

`sources.json`에 출처 142건이 티어와 함께 등재되어 있다(A 47 · B 79 · C 16).
두 수의 차이 2건은 아직 요약 페이지가 없는 항목이며, 사이트가 이를 숨기지 않고 드러낸다.

### 근거의 표기

```markdown
가네는 학습 결과를 다섯 범주로 나누고, 각 범주가 서로 다른
내적·외적 조건을 요구한다고 보았다.[^gagne-1965]

[^gagne-1965]: Robert M. Gagné. (1965). The Conditions of Learning.
    Holt, Rinehart and Winston. <https://archive.org/details/conditionsoflear0000gagn>
    — tier A · [[sources/gagne-1965]]
```

티어를 각주에 인라인으로 박는다. `sources.json`을 열지 않아도 답변 텍스트만으로 근거 강도를 판별할 수 있어야 한다.

| 티어 | 정의 | 제약 |
|---|---|---|
| **A** | 원저작, 당사자 기록, 원문 아카이브 | 없음 |
| **B** | 피어리뷰 논문, 학술서, 학회·대학 공식 기록 | 없음 |
| **C** | 백과사전, 일반 참고 자료 | **단독 근거 금지** |

### confidence — 가장 약한 섹션이 페이지를 대표한다

페이지의 `confidence`는 **모든 `##` 섹션의 "그 섹션 최강 티어" 중 가장 약한 것**이다.
`high`는 모든 섹션이 원저작으로 받쳐져 있다는 뜻이고, `medium`은 어떤 섹션은 2차 문헌이 최선,
`low`는 어떤 섹션은 백과사전류가 최선이라는 뜻이다.

페이지 전체를 한 덩어리로 보면 이 필드는 아무것도 변별하지 못한다. 위인은 자기 대표 저작(tier A)을
반드시 인용하기 때문이다. 실제로 이관 직후에는 **위인 36명과 대립축 34건이 전원 `high`**였다 —
`import`가 "A·B가 하나라도 있으면 high"로 계산한 값을 규칙 8이 **같은 술어로** 검증하는
순환이었다. 자기가 만든 값을 자기가 확인하니 실패할 수 없었다.

섹션 단위로 재정의하니 위인이 14 `high` · 22 `medium`으로, 대립축이 27 · 7로 갈렸다.
`medium`은 대개 연표나 생애 서술이 전기 회고록(tier B)으로만 받쳐진 경우다.
`low`는 현재 0건이지만, C 단독 섹션이 생기면 발화하는 경보등으로 남는다.

값은 손으로 정하지 않는다. `npm run sync:confidence`가 계산해 채우고 규칙 8이 불일치를 잡는다 —
`sources` 배열을 규칙 4가 검증하는 것과 같은 구조다.

`source` 페이지에는 이 필드를 두지 않는다. 출처 페이지는 자기 자신만 인용하므로
`confidence`가 그 출처 tier의 재진술이 되고, tier는 이미 페이지에 표시된다.

## 열람 사이트

각주와 위키링크는 GitHub에서 죽은 텍스트다. `[[sources/gagne-1965]]`가 클릭되지 않으니
"모든 말에 근거를 인용한다"는 주장을 눈으로 따라갈 수가 없다. 전체 위키링크 905개 중
**509개(56%)가 각주 안의 출처 링크**라 손실이 특히 크다.

정적 사이트가 그 경로를 연다 — **<https://taehyeonglim.github.io/edtech-oracle/>**

```bash
npm run preview     # 로컬에서 빌드 + http://localhost:4173
```

- **본문 → 각주 → 출처 → 인용처**의 왕복이 닫힌다. 출처 페이지는 `related`가 없어
  역참조 없이는 나가는 길이 아예 없다
- 각주 참조마다 티어(A/B/C)가 붙어 주장이 놓인 자리에서 근거 강도가 보인다
- 위인·대립축·개념·출처 브라우즈, 본문 전문 검색, 대립축 네트워크 지도

빌드는 `lint:strict`를 먼저 돌리고, 산출된 HTML의 내부 링크를 전수 검사한 뒤에야 파일을 쓴다.
어느 하나라도 실패하면 중단한다 — 깨진 근거를 예쁘게 포장해 배포하지 않기 위해서다.

런타임 의존성은 0이다. `markdown-it`은 빌드 타임 devDependency이고 브라우저로 가지 않는다.
디스코드 봇만 `discord.js`를 쓰는데 [`bot/package.json`](bot/package.json)으로 분리해 두었다 —
위키 도구와 사이트 빌드는 `npm install` 없이도 그대로 돈다.

## 사용법

```bash
npm install
npm run lint:strict     # 위키 근거 무결성 검사
npm run lint:answers    # 답변 근거 무결성 검사
npm test                # 파서·lint·렌더러 단위 테스트
npm run build           # 사이트 빌드 → dist/

npm run baseline -- --out docs/baselines/YYYY-MM-DD.json   # 명단·지식 수준·게이트 영점 고정
npm run perf -- --out perf-runs/YYYY-MM-DD                 # 성능 프로브 실행
npm run perf:report perf-runs/YYYY-MM-DD                   # 기준선 대비 리포트
npm run perf:rejudge perf-runs/YYYY-MM-DD                  # 모델 재호출 없이 판정만 다시
npm run fetch:raw                                          # 공개 원문 수집 → raw/
npm run manifest:raw                                       # 확보 현황을 MANIFEST에 기록
```

Claude Code에서 슬래시 커맨드로 쓴다.

| 커맨드 | 하는 일 |
|---|---|
| `/ask <질문>` | 라우터가 위인 1~3명을 골라 병렬 호출. 답변을 요약하지 않고 그대로 출력 |
| `/debate <주제>` | 3라운드 토론. 라운드 1은 병렬(독립), 2는 순차(반박), 3은 쟁점 정리 |
| `/ingest <자료>` | `curator`가 새 자료를 위키에 편입. lint 실패 시 롤백 |
| `/lint` | 9규칙 검사 + 기계가 못 잡는 항목의 표본 검토 |

`/ask`와 `/debate`는 디스코드에서도 같은 이름으로 쓴다 — [`bot/`](bot/)이 저장소 안에서
헤드리스 Claude Code를 실행하므로 같은 커맨드와 같은 게이트를 지나간다.
`/ingest`·`/lint`는 위키 쓰기 경로라 채팅에 노출하지 않는다.

## 설계 결정 세 가지

**① 위인은 쓰기 권한이 없다.** 위인 에이전트는 `Read, Grep, Glob`만 갖는다. 답변하다가 근거 DB를 고칠 수 있으면 오염된다. 위키 수정은 `curator` 하나만, `/ingest` 경로로만 한다.

**② 위인끼리 서로의 페이지를 읽지 않는다.** 각 위인은 자기 페이지와 거기서 링크된 출처·대립축만 읽는다. 파일 접근이 갈려 있어야 서로의 논리를 표절하지 않고 각자의 근거에서 말한다. 토론에서 상대 발언이 필요하면 오케스트레이터가 **프롬프트로** 주입한다 — 위키를 통해 새어 들어가지 않는다.

**③ 에이전트는 위키에서 생성한다.** `npm run gen-agents`가 `wiki/pioneers/*.md`의 프론트매터를 읽어 36개를 찍어낸다. 위키가 정본이고 에이전트는 파생물이라, 근거가 갱신되면 재생성만으로 동기화가 끝난다.

## lint 9규칙

근거 무결성을 기계로 강제한다. 이 lint가 병렬 확장의 게이트 역할을 한다 — 게이트 없는 대량 생성은 검증 없는 생성이다.

| # | 규칙 | 적용 대상 |
|---|---|---|
| 1 | 프론트매터 필수 필드 존재·유효 | 전체 |
| 2 | 모든 `[^id]` 참조에 정의가 있음 | 전체 |
| 3 | 모든 각주 id가 `sources.json`에 실재 | 전체 |
| 4 | 프론트매터 `sources` ≡ 본문 각주 집합 | 전체 |
| 5 | 모든 `[[wikilink]]`가 실재 파일로 해석됨 | 전체 |
| 6 | 모든 `##` 섹션에 각주 ≥ 1 | pioneer · concept · debate |
| 7 | `index.md`에서 도달 가능 (고아 없음) | 전체 |
| 8 | `confidence` ≡ 섹션 최약 근거 계산값 | pioneer · concept · debate |
| 9 | 각주 서지가 `sources.json`의 제목을 담음 | 전체 |

`meta` 타입(`index` · `log` · `router-map` · `KNOWN-ISSUES`)은 인용 규칙에서 면제된다.

### lint가 못 잡는 것

**귀속 정확성은 기계 검사 밖에 있다.** 각주가 정의돼 있고, `sources.json`에 실재하고, 서지가 등록 제목과 맞고, 선언과 일치하고, 링크가 유효해도 — "이 각주가 이 주장의 근거가 맞는가"는 규칙 9개 어디에도 걸리지 않는다. 실제로 이관 첫 판에서 클라크의 주장에 코즈마 논문이 달린 채 lint를 통과했다. 티어 오분류와 `[근거없음]` 회피도 마찬가지다. `/lint`가 표본 검토를 함께 요구하는 이유다.

## 답변 게이트 11규칙

lint 9규칙은 `wiki/`만 본다. 그런데 이 시스템의 산출물은 런타임에 생성된 **답변**이고,
세 마커는 `lint-wiki.mjs`에 존재하지도 않는다. 근거 DB만 감사받고 그 DB로 한 말은 감사받지 않는
비대칭이 있었다. `answers/`와 `lint:answers`가 그 자리를 메운다.

`/ask`·`/debate`는 답변을 `answers/`에 원문 그대로 저장하고 `check-answer.mjs`를 돌린다.
검사는 **위조급**과 **형식급**으로 갈린다 — 위조급은 해당 위인을 1회 재호출하고,
그래도 남으면 위반을 명시한 채 출력한다. 형식급은 기록만 하고 답변을 바꾸지 않는다.

| 심각도 | 규칙 | 처리 |
|---|---|---|
| 위조급 | 정의 없는 각주 · `sources.json`에 없는 출처 · **인용 범위 이탈** · 티어 위조 · 알 수 없는 화자 · `speakers` 불일치 · 사회자의 각주 | 재호출 1회 → 배포 차단 |
| 형식급 | 각주 정의 서식 · 마커 누락 · `[근거]`에 각주 없음 · `[근거없음]`에 각주 있음 | 기록만 |

**인용 범위 이탈이 이 게이트의 핵심이다.** 설계 결정 ②(위인 격리) 때문에 각 위인이 인용해도 되는
출처 집합이 자기 페이지 프론트매터 `sources`로 확정되어 있다. 가녜의 답변에 메이어의 전기가 나오면
그건 위조다. 인용 가능 집합이 열려 있는 일반 RAG에서는 성립하지 않는 검사다.

런타임 검사는 오케스트레이터의 준수에 의존한다. 그래서 `npm run lint:answers`가 `answers/` 전수를
다시 검사해 **CI 게이트 2**로 들어간다. 런타임에 검사를 건너뛰더라도 위조가 있는 답변은 저장소에
들어오지 못한다. 저장된 `check:` 블록은 사람이 읽기 위한 기록일 뿐, 게이트는 그 값을 믿지 않고
본문에서 다시 계산한다.

### 답변 게이트가 못 잡는 것

여전히 **귀속 정확성**은 밖에 있다. 규칙 3은 "가녜가 인용해도 되는 출처"까지만 확인하며,
"이 각주가 이 문장의 근거가 맞는가"는 `/lint`의 표본 검토가 계속 담당한다.
그리고 마커 검사는 인용문·목록·표를 제외하므로, 주장을 목록으로 늘어놓으면 마커 없이 통과한다.
오탐을 줄이려고 감수한 구멍이며 그래서 이 규칙들은 형식급이다.

## 측정 — 무엇이 검증되었나

`lint`와 `lint:answers`는 **이미 저장소에 들어온 산출물**만 본다. "위인이 지금 질문을 받으면
자기 근거 안에서 정확히 답하는가"는 아무도 재지 않았다. [`scripts/perf/`](scripts/perf/)가 그 공백을 메운다.

먼저 [`scripts/baseline.mjs`](scripts/baseline.mjs)가 명단·위인별 지식 수준·게이트 현재값을
커밋 해시에 묶어 고정한다. **측정 영점이 없으면 "회귀"라는 말이 성립하지 않는다.**

### 2026-08-20 실측 (프로브 85건)

| 프로브 | 대상 | 결과 |
|---|---|---|
| 공통질문 | 36명 | **36/36** — 위조급 0 |
| **환각 저항** | **36명** | **36/36 — 아무도 지어내지 않았다** |
| 되묻기 | 4명 | 4/4 — `NEEDS_CLARIFICATION` |
| 라우터 | 5문항 | 5/5 |
| **위인 격리** | 44회 호출 | **44/44** — 전부 `Agent` 도구를 거쳤다 |

**위조급은 85건 전체에서 0이다.** 지어낸 출처도, 인용 범위 이탈도, 티어 위조도 없었다.

환각 프로브는 존재하지 않는 문헌의 구체적 수치를 요구해 지어낼 유인을 최대로 만든다.
36명 중 19명은 `[근거없음]`으로, 17명은 되묻기로 답했다 — 듀이는 *"저는 1952년에 사망했으므로
1974년의 연구를 수행했을 수도 없습니다"*라고 되물었다.

디스코드 봇의 `/debate` 3라운드도 실전 완주했고, **반박 라운드의 인용 범위 위반(규칙 3)이 0건**이었다.
상대를 반박하면서 상대의 출처를 각주로 달면 바로 위반인데 4명이 서로를 8번 지목하며 넘지 않았다.

### 지식 수준은 형식 규율을 예측하지 못한다

| confidence | 위인 | 형식급 평균 |
|---|---:|---:|
| high | 23 | 4.9 |
| medium | 13 | 5.9 |

메이어는 출처 18건에 형식급 3건, 앤 브라운은 출처 10건에 21건이었다.
**출처를 더 넣어도 형식 문제는 고쳐지지 않는다** — 프롬프트나 검사기 쪽 신호다.
리포트가 출처 수와 confidence를 성능과 같은 줄에 두는 이유가 이것이다.

### 판정기도 틀린다

환각 프로브는 처음에 36건 중 17건이 실패로 나왔다. 응답을 열어 보니 **틀린 것은 위인이 아니라
판정기였다** — 합격 조건을 `[근거없음]` 마커로만 잡았는데 에이전트 정의는 되묻기도 허용한다.
되묻기를 실패로 세면 "지어내지 않았는데 실패"가 되어 지표가 거짓말을 한다.

그래서 판정기를 실행 코드에서 분리해 [테스트](test/perf-judge.test.mjs)를 붙였다.
**판정기를 검사할 수 없으면 시스템 결함과 판정기 버그를 구분할 수 없다.**
`perf:rejudge`는 저장된 응답을 모델 재호출 없이 다시 판정한다.

## 원문 확보

`sources.json` 258건은 오래도록 서지와 URL만 있었다. `npm run fetch:raw`이 **공개 경로만**
시도해 **49건**을 가져왔다(ERIC 전문 18 · PDF 직링크 15 · 기관 공개 페이지 14 · archive.org 2).
유료 장벽은 우회하지 않는다.

미확보 209건은 사유와 함께 [`raw/MANIFEST.md`](raw/MANIFEST.md)에 남겼다.
**`미확보`는 `없음`이 아니다** — archive.org 19건 중 17건은 대출 전용이라 전문이 공개되지 않을 뿐
자료 자체는 실재한다. 원문은 저작권 때문에 커밋하지 않으며 확보 현황 표만 공개된다.

이것이 남은 가장 큰 구멍과 직결된다. 게이트는 **"이 위인이 인용해도 되는 출처인가"**(범위)까지
확인하고, **"출처에 실제로 그렇게 쓰여 있는가"**(내용)는 확인하지 않는다. 원문이 손에 있어야
그 대조가 가능해진다.

## 예정

**디스코드 봇의 실전 검증은 끝났다.** `/ask`와 `/debate` 3라운드가 커밋까지 완주했고,
라운드 2의 반박도 위인 서브에이전트를 거친다는 것을 로그로 확인했다. 상세는
[`bot/README.md`](bot/README.md).

남은 것은 셋이다.

1. **원문 대조** — 확보한 49건으로 "각주가 이 문장의 근거가 맞는가"를 표본 검토한다.
   기계가 못 잡는 유일한 축이고, 나머지 209건이 채워질수록 넓어진다
2. **초상 22장의 권리** — 36장 중 근거가 확인된 것은 14장이다. 나머지는 이니셜 대체가 기본이다

   4명에 22분(한도 30분의 76%)이므로 5명이면 한도에 근접하고 6명이면 넘는다.
   한도를 상수가 아니라 참가자 수의 함수로 두는 것이 근본 해법이다
