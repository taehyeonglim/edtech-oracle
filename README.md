# 에듀테크 오라클

에듀테크에 관해 물으면 **교육공학의 위인 36인이 등장해 학술적 근거를 인용하며** 답한다. 한 명이 답하기도 하고 여러 명이 갈리기도 하며, 서로 토론하기도 한다.

선행 프로젝트 [edtech-pantheon](https://github.com/taehyeonglim/edtech-pantheon)이 교육공학을 **읽는** 아카이브라면, 오라클은 같은 근거로 **말하는** 시스템이다.

> **현재 상태 — 초기 구축**
>
> 위인 36인의 근거 위키와 서브에이전트가 동작하고, 근거를 따라갈 수 있는 [열람 사이트](#열람-사이트)가 있다.
> 질문을 던지는 대화 프론트엔드는 아직 Claude Code 슬래시 커맨드뿐이다.
> 위인 33인의 비판·한계 서술은 `gpt-5.6-luna`가 생성했으며, 2026-08-14에 33인 전수 감사(각주-출처
> 정합성·상대 위인 페이지와의 모순·티어 오분류·근거 없는 단정 서술)를 마쳐 귀속 오류는 발견되지
> 않았다. [알려진 이슈](#알려진-이슈)를 함께 읽기 바란다.

## 무엇이 다른가

이 프로젝트의 제약은 하나다 — **모든 말에 근거를 인용한다.**

그래서 위인들은 세 가지 마커 중 하나를 달고 말한다.

```
[근거]     내 문헌에 직접 있는 주장. 각주 필수
[적용]     내 원리를 현대 상황에 적용한 추론. 출발 원리의 각주 + 추론임을 명시
[근거없음] 내 문헌에 근거가 없다. 지어내지 않는다
```

`[적용]`이 필요한 이유는 시대 격차다. 사용자 질문은 대부분 생성형 AI·LMS·마이크로러닝인데 위인들은 1900~2000년대 인물이다. 마커가 없으면 "가네가 AI 튜터에 대해 이렇게 말했다"는 문장이 근거 있는 주장처럼 유통된다.

`[근거없음]`은 회피가 아니라 정직성 장치다. 이게 없으면 위인들은 그럴듯하게 지어낸다.

## 구조

Karpathy의 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 패턴을 따른다 — 3계층과 3오퍼레이션만 고정이고 스키마는 도메인에 맞게 설계했다.

```
raw/          Layer 1 · 불변 원자료 (gitignore, 목록만 MANIFEST.md로 공개)
wiki/         Layer 2 · 에이전트가 유지하는 마크다운
CLAUDE.md     Layer 3 · 스키마 정본
```

```
wiki/
├── index.md · log.md · router-map.md · KNOWN-ISSUES.md   type: meta
├── pioneers/   36   위인의 정체성과 자기 입장
├── debates/    34   대립축 (Clark–Kozma 매체 효과 논쟁 등)
├── concepts/    3   개념 정본 — 유기적으로 자란다
└── sources/   140   출처 요약
```

`sources.json`에 출처 142건이 티어와 함께 등재되어 있다(A 47 · B 79 · C 16).
두 수의 차이 2건은 아직 요약 페이지가 없는 항목이며, 사이트가 이를 숨기지 않고 드러낸다.

### 근거의 표기

```markdown
가네는 학습 결과를 다섯 범주로 나누고, 각 범주가 서로 다른
내적·외적 조건을 요구한다고 보았다.[^gagne-1965]

[^gagne-1965]: Robert M. Gagné. (1965). The Conditions of Learning.
    Holt, Rinehart and Winston. <https://archive.org/details/conditionsoflear0000gagn>
    — tier A · [[sources/gagne-1965]]
```

티어를 각주에 인라인으로 박는다. `sources.json`을 열지 않아도 답변 텍스트만으로 근거 강도를 판별할 수 있어야 한다.

| 티어 | 정의 | 제약 |
|---|---|---|
| **A** | 원저작, 당사자 기록, 원문 아카이브 | 없음 |
| **B** | 피어리뷰 논문, 학술서, 학회·대학 공식 기록 | 없음 |
| **C** | 백과사전, 일반 참고 자료 | **단독 근거 금지** |

## 열람 사이트

각주와 위키링크는 GitHub에서 죽은 텍스트다. `[[sources/gagne-1965]]`가 클릭되지 않으니
"모든 말에 근거를 인용한다"는 주장을 눈으로 따라갈 수가 없다. 전체 위키링크 905개 중
**509개(56%)가 각주 안의 출처 링크**라 손실이 특히 크다.

정적 사이트가 그 경로를 연다.

```bash
npm run preview     # 빌드 + http://localhost:4173
```

- **본문 → 각주 → 출처 → 인용처**의 왕복이 닫힌다. 출처 페이지는 `related`가 없어
  역참조 없이는 나가는 길이 아예 없다
- 각주 참조마다 티어(A/B/C)가 붙어 주장이 놓인 자리에서 근거 강도가 보인다
- 위인·대립축·개념·출처 브라우즈, 본문 전문 검색, 대립축 네트워크 지도

빌드는 `lint:strict`를 먼저 돌리고, 산출된 HTML의 내부 링크를 전수 검사한 뒤에야 파일을 쓴다.
어느 하나라도 실패하면 중단한다 — 깨진 근거를 예쁘게 포장해 배포하지 않기 위해서다.

런타임 의존성은 0이다. `markdown-it`은 빌드 타임 devDependency이고 브라우저로 가지 않는다.

## 사용법

```bash
npm install
npm run lint:strict     # 근거 무결성 검사
npm test                # 파서·lint·렌더러 단위 테스트
npm run build           # 사이트 빌드 → dist/
```

Claude Code에서 슬래시 커맨드로 쓴다.

| 커맨드 | 하는 일 |
|---|---|
| `/ask <질문>` | 라우터가 위인 1~3명을 골라 병렬 호출. 답변을 요약하지 않고 그대로 출력 |
| `/debate <주제>` | 3라운드 토론. 라운드 1은 병렬(독립), 2는 순차(반박), 3은 쟁점 정리 |
| `/ingest <자료>` | `curator`가 새 자료를 위키에 편입. lint 실패 시 롤백 |
| `/lint` | 8규칙 검사 + 기계가 못 잡는 항목의 표본 검토 |

## 설계 결정 세 가지

**① 위인은 쓰기 권한이 없다.** 위인 에이전트는 `Read, Grep, Glob`만 갖는다. 답변하다가 근거 DB를 고칠 수 있으면 오염된다. 위키 수정은 `curator` 하나만, `/ingest` 경로로만 한다.

**② 위인끼리 서로의 페이지를 읽지 않는다.** 각 위인은 자기 페이지와 거기서 링크된 출처·대립축만 읽는다. 파일 접근이 갈려 있어야 서로의 논리를 표절하지 않고 각자의 근거에서 말한다. 토론에서 상대 발언이 필요하면 오케스트레이터가 **프롬프트로** 주입한다 — 위키를 통해 새어 들어가지 않는다.

**③ 에이전트는 위키에서 생성한다.** `npm run gen-agents`가 `wiki/pioneers/*.md`의 프론트매터를 읽어 36개를 찍어낸다. 위키가 정본이고 에이전트는 파생물이라, 근거가 갱신되면 재생성만으로 동기화가 끝난다.

## lint 8규칙

근거 무결성을 기계로 강제한다. 이 lint가 병렬 확장의 게이트 역할을 한다 — 게이트 없는 대량 생성은 검증 없는 생성이다.

| # | 규칙 | 적용 대상 |
|---|---|---|
| 1 | 프론트매터 필수 필드 존재·유효 | 전체 |
| 2 | 모든 `[^id]` 참조에 정의가 있음 | 전체 |
| 3 | 모든 각주 id가 `sources.json`에 실재 | 전체 |
| 4 | 프론트매터 `sources` ≡ 본문 각주 집합 | 전체 |
| 5 | 모든 `[[wikilink]]`가 실재 파일로 해석됨 | 전체 |
| 6 | 모든 `##` 섹션에 각주 ≥ 1 | pioneer · concept · debate |
| 7 | `index.md`에서 도달 가능 (고아 없음) | 전체 |
| 8 | `confidence: high`는 A·B 티어 ≥ 1 | pioneer · concept · debate |

`meta` 타입(`index` · `log` · `router-map` · `KNOWN-ISSUES`)은 인용 규칙에서 면제된다.

### lint가 못 잡는 것

**귀속 정확성은 기계 검사 밖에 있다.** 각주가 정의돼 있고, `sources.json`에 실재하고, 선언과 일치하고, 링크가 유효해도 — "이 각주가 이 주장의 근거가 맞는가"는 규칙 8개 어디에도 걸리지 않는다. 실제로 이관 첫 판에서 클라크의 주장에 코즈마 논문이 달린 채 lint를 통과했다. 티어 오분류와 `[근거없음]` 회피도 마찬가지다. `/lint`가 표본 검토를 함께 요구하는 이유다.

## 알려진 이슈

pantheon README가 공개한 P1 이슈를 그대로 물려받았다. 전체 목록은 [`wiki/KNOWN-ISSUES.md`](wiki/KNOWN-ISSUES.md)에 있다.

1. ~~**Ann L. Brown / John Seely Brown 혼동**~~ — 해결됨(2026-08-14). 인지적 도제는 이미 Collins·Brown·Newman에게 정확히 귀속되어 있었다
2. **관계 근거의 추적성 부족** — 페이지·DOI·접근일 메타데이터 불완전
3. **초상 이미지 권리** — 36장 중 명확한 것은 14장. 디스코드 단계에서 나머지는 이니셜 대체
4. **서지·연표의 직접 근거 부족** — 부분 해결(2026-08-14). Bloom·Gagné·Bruner·Merrill·Keller·Papert의 오귀속 6건을 당대 문헌으로 교체했다. Papert의 1967년 Logo turtle 사건은 당대 1차 문헌을 찾지 못해 미해결로 남는다
5. **전기의 C 티어 의존** — 부분 해결(2026-08-14). 12명(듀이·손다이크·비고츠키·스키너·블룸·가녜·브루너·반두라·메릴·켈러·파퍼트·메이어)에 tier B 전기 출처를 병행 인용으로 추가했다. 나머지 위인들과 대체 출처를 찾지 못한 4건(`bio-dick-authority` 등)은 여전히 C 티어에 의존한다

여기에 이 프로젝트가 새로 안았던 것이 하나 더 있다.

6. ~~**확장분의 검토 미완**~~ — 해결됨(2026-08-14). 위인 33인의 `당대의 비판`·`한계` 섹션은 `gpt-5.6-luna`가 배치별로 생성하고 lint 게이트를 통과한 것이었다. 6개 서브에이전트가 33인 전원을 병렬 전수 감사(각주-출처 정합성·상대 위인 페이지와의 모순·티어 오분류·근거 없는 단정 서술)했고 귀속 오류는 발견되지 않았다. 생성 지시서는 [`.codex-tasks/`](.codex-tasks/)에 커밋되어 있어 어떤 지시가 어떤 문장을 만들었는지 추적할 수 있다.

## 예정

**대화 프론트엔드(디스코드 또는 웹).** 채널 입력을 받아 라우팅하고, 위인들이 각자의 프로필 이미지를 달고 등장한다.

이전 README는 "어댑터만 얹으면 된다"고 썼지만 그건 과소평가였다. 읽는 쪽은 실제로 그랬다 —
열람 사이트는 `wiki-parse.mjs`를 그대로 재사용해 만들었다. 그러나 **말하는 쪽은 다르다**:
`/debate`의 라운드 상태머신과 `NEEDS_CLARIFICATION` 되묻기 왕복이 Claude Code 세션의 대화
상태에 얹혀 있어서, 옮기려면 오케스트레이터를 새로 써야 한다. 초상 22장의 권리도 미해결이다.
