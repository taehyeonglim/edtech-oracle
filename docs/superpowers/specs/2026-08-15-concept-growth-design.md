# 개념 성장 경로 — 설계 명세

**날짜** 2026-08-15
**상태** 승인됨 (도구 단계). 승격 단계는 후보 목록 승인 후 진행

## 문제

`concepts/`가 3개에서 자라지 않는다. `CLAUDE.md`는 "유기적으로 자란다"고 쓰고
확장 작업이 `proposed_concepts`로 제안하게 되어 있지만, **사용 0건**이다.

측정하니 원인이 둘이었다.

### 1. `proposed_concepts`에 소비자가 없다

`scripts/`·`test/` 어디에도 이 필드를 읽는 코드가 없다. `make-expansion-batches.mjs`의
지시문, `CLAUDE.md`, `.codex-tasks/` 배치 파일의 **산문에만** 존재한다.
써도 아무 데도 나타나지 않으므로, 확장 배치가 지시를 받고도 제안하지 않은 것이 자연스럽다.

### 2. 공유 개념 탐지가 정확 문자열 일치다

위인 36명의 `concepts` 필드에 문자열 144개가 있고 고유값이 141개다.
2회 이상 등장하는 것이 정확히 3개이며, 그것이 개념 페이지 3개다.
즉 `concepts/`의 크기는 **어휘 통제 부재의 직접적 결과**이지 교육공학에 공유 개념이
3개뿐이어서가 아니다.

실제로 데이터에 이미 공유 개념이 있다. 예:

| 위인 A | 위인 B | 관계 |
|---|---|---|
| `준거참조평가` (글레이저) | `준거지향 평가` (메이거) | 같은 개념의 다른 번역어 |
| `설계연구` (콜린스) | `설계실험` (앤 브라운) | 같은 방법론의 다른 이름 |
| `인지부하` (스웰러) | `외재적 인지부하` (메이어) | 상위-하위 |
| `학습자 중심성` (듀이) | `학습자 중심 체제` (라이겔루스) | 같은 계열 |

## 기계의 한계 — 명시한다

문자열 유사도로는 진짜와 가짜를 가를 수 없다.

```
설계연구 ↔ 설계실험   진짜 (design research / design experiment)
교수기계 ↔ 교수기술   가짜 (teaching machine / instructional technology)
```

둘 다 "같은 2자 접두사 + 다른 2자 접미사"다. 한국어 2음절 접두사(인지·교수·설계·평가·교육)가
잡음의 대부분을 만든다. 근본 원인은 `concepts`가 **한국어 표시 레이블**이지 식별자가 아니라는
것이다. 개념 파일명은 이미 ASCII 슬러그를 쓰지만(`community-of-practice`) 이 규율이
`concepts` 필드에는 없다.

어휘 통제(각 항목에 정규 키 부여)가 근본 해결이지만 141개 문자열에 대한 판단이 필요하고,
그 판단이 데이터에 고정된다. 후보 리포트를 먼저 만들고, 검토 결과가 쌓이면 그것이 곧
통제 어휘가 된다. 지금은 만들지 않는다.

## 탐지 — 강·약 2단

정규화는 공백·가운뎃점·붙임표를 제거하고 소문자화한다.

| 단 | 판정 |
|---|---|
| **강** | 정규화 후 정확 일치 · 포함(짧은 쪽 ≥ 3자) · 편집거리 비율 ≤ 0.34 |
| **약** | 편집거리 비율 ≤ 0.5 |

정규화는 **NFKC를 먼저 건다.** macOS가 같은 한글을 NFD(자모 분해)로 넘길 때가 있어
정규화 없이 비교하면 눈에 같은 글자가 다른 개념이 되고, `.length`도 늘어나 3자 하한이
무력해진다. 전각 `ＡＲＣＳ`도 여기서 `ARCS`가 된다.

접두사 전용 규칙은 두지 않는다. 공통 접두사가 절반 이상이면 편집거리 비율이 반드시 0.5 이하라
약한 편집거리 분기가 먼저 반환한다 — 별도 분기는 도달할 수 없는 죽은 코드가 된다.

접두사 규칙을 버리면 `설계연구↔설계실험`이 떨어지고, 살리면 `교수기계↔교수분석`이 들어온다.
기계가 못 가르므로 **가르는 척하지 않고 두 단으로 표시해 사람에게 넘긴다.**
같은 위인 안의 두 개념은 비교하지 않는다 — 공유 개념을 찾는 것이 목적이다.

포함 판정에 짧은 쪽 ≥ 3자 조건을 두는 이유는 2자 개념이 잡음을 만들기 때문이다
(`주의`가 `민주주의와 교육`·`연결주의`·`구성주의 학습환경`에 포함된다).

```
scripts/concept-candidates.mjs     후보 탐지 + proposed_concepts 수집
test/concept-candidates.test.mjs   판정 규칙 단위 테스트
package.json                       concepts:candidates 스크립트
```

```js
export function conceptCandidates({ wikiDir })
// → { strong: [{a, b, why}], weak: [...], proposed: [{slug, name}] }
```

순수 함수다. 위키를 읽되 쓰지 않는다. 서식은 CLAUDE 계층이 맡는다.

`proposed` 수집이 이 필드에 처음으로 소비자를 준다. 현재 0건이지만 도구가 생기면
다음 확장 배치의 지시가 실효를 갖는다.

## 승격 (별도 단계)

도구 출력을 사람이 검토하고 승인한 것만 개념 페이지로 만든다. 조건은 둘이다.

1. 두 위인의 개념이 실제로 같은 개념인가 — 사람 판정
2. 양쪽 위인 페이지가 그 개념에 대해 이미 A·B 티어 각주를 갖는가 —
   `CLAUDE.md`의 "새 개념 페이지는 `sources.json`에 근거가 있을 때만" 규칙

승격 시 지켜야 할 계약은 기존 3개 페이지에서 관찰한 것과 같다.

- `wiki/concepts/<ascii-slug>.md` — 파일명은 ASCII 슬러그(macOS 유니코드 정규화 회피)
- 프론트매터 `title` · `type: concept` · `related` · `updated` · `sources` · `confidence`
- 본문 `## 이 개념을 공유하는 위인` + `## 상태`
- `wiki/index.md`의 `## 개념 (N)` 절에 등재하고 개수를 갱신한다 — 규칙 7(고아 없음)
- `confidence`는 손으로 정하지 않는다. `npm run sync:confidence`가 채운다

## 범위 밖

- 어휘 통제(ASCII 정규 키) 도입 — 후보 검토 결과가 쌓인 뒤에 판단한다
- `concepts` 필드 자체의 재작성 — 위인의 자기 어휘이므로 함부로 통일하지 않는다
- 개념 페이지의 정본 정의 작성 — 기존 3개도 `## 상태`에 "정본 정의는 아직
  작성되지 않았다"고 적혀 있다. 같은 상태로 만든다
