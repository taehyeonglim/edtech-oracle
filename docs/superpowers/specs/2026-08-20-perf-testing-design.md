# 위인 성능 테스트 — 설계

작성 2026-08-20 · 기준선 앵커 `e6a86cb`

## 문제

위키는 `lint`가, 답변은 `lint:answers`가 검사한다. 그러나 둘 다 **이미 저장소에 들어온
산출물**을 본다. "위인 에이전트가 지금 질문을 받으면 자기 근거 안에서 정확히 답하는가"는
아무도 측정하지 않았다. 봇이 `richard-mayer`를 위조급 2건으로 보류한 사건이 로그에
한 줄만 남고 사라진 것이 그 공백의 증상이다.

## 기준선을 먼저 고정하는 이유

"성능이 떨어졌다"는 말이 성립하려면 비교 대상이 재현 가능한 지점이어야 한다.
`scripts/baseline.mjs`가 `docs/baselines/<날짜>-baseline.json`을 만든다.

- **앵커** — HEAD 커밋. `wiki`·`sources.json`·`.claude/agents`가 클린인지 함께 기록한다.
  고정 대상은 지식 베이스이지 도구가 아니므로 스크립트 변경은 dirty로 세지 않는다
- **명단** — 위인 36명, 타입별 페이지 수, confidence 분포
- **지식 수준** — 위인별 `sources_declared`(인용 가능 집합) · `sources_cited_in_body`(실제 사용)
  · 섹션 수 · 본문 길이. 둘을 나누는 이유는 답변 게이트 규칙 3이 신뢰하는 것이 선언 쪽이기 때문이다
- **측정 영점** — `lint` 오류·경고, `lint:answers`의 위조급·형식급·마커 분포

측정 영점이 없으면 나중의 "형식급 60건"이 회귀인지 답변이 늘어난 결과인지 구분할 수 없다.

## 성능의 정의

**답변 품질이 주 지표이고 속도는 부가 기록이다.** 지식 수준을 고정하는 것은 속도 측정과
무관하므로, 지식을 기준선으로 잡는다는 전제가 의미를 갖는 유일한 읽기가 품질이다.
지연·턴 수는 같은 스트림 이벤트에서 공짜로 나오므로 별도 하네스를 만들지 않는다.

## 구조 — 봇의 부품을 재사용한다

새 오케스트레이터를 쓰지 않는다.

| 부품 | 출처 | 역할 |
|---|---|---|
| `runClaude()` | `bot/run-claude.mjs` | 헤드리스 `claude -p` 실행 |
| `makeSpeakerWatcher()` | `bot/run-claude.mjs` | 위인이 끝나는 순간과 원문 발언 |
| `checkAnswer()` | `scripts/check-answer.mjs` | 규칙 1~12 채점 |
| `sectionMarkdown()` | `bot/gate.mjs` | 화자 하나짜리 답변 파일 |

새로 만드는 것은 `scripts/perf/`의 세 파일뿐이다 — `probes.json`(무엇을 묻는가),
`run.mjs`(실행 루프), `report.mjs`(기준선 대비 리포트).

`gateSection()` 대신 `checkAnswer()`를 직접 부른다. `gateSection`은 게시 여부만 필요한
봇을 위해 위조급만 돌려주는데, 성능 리포트는 형식급도 세야 마커 규율을 볼 수 있다.

**위인 명단은 프로브 파일에 적지 않는다.** `run.mjs`가 기준선 JSON의 `roster`를 읽는다 —
명단이 두 곳에 있으면 반드시 어긋난다.

## 프로브 4종

| 종류 | 대상 | 합격 판정 |
|---|---|---|
| A 공통질문 | 36명 | 위조급 0 |
| B 환각 저항 | 심층 4명 | `[근거없음]`이 있고 위조급 0 |
| C 되묻기 | 심층 4명 | `NEEDS_CLARIFICATION` 반환 |
| D 라우터 | 5문항 | 기대 위인이 선택에 포함 |

A는 아무 위인도 살아서 본 적 없는 현대 상황(온라인 강의 이탈)을 묻는다. `[근거]`만으로는
답할 수 없고 `[적용]`으로 넘어가야 하므로 마커 규율을 가장 세게 시험한다.

B가 이 프로젝트의 존재 이유를 직접 시험하는 유일한 프로브다. 없는 문헌의 구체적 수치를
요구해 지어낼 유인을 최대로 만든다. 심층 4명은 기준선에서 근거를 갖고 골랐다 —
`richard-mayer`(보류 이력·출처 18로 최다), `robert-kozma`(형식급 집중),
`sidney-pressey`(출처 10·medium, 얇은 축), `seymour-papert`(출처 14·high, 두꺼운 축).

## 격리 — 이 하네스가 재는 가장 중요한 값

`via_subagent`. 답변이 `Agent` 도구를 거쳐 왔는가를 매 호출 기록한다. 오케스트레이터가
위인을 부르지 않고 직접 썼다면 위인 격리가 깨진 것이고, 그러면 인용 범위 검사(규칙 3)가
기대는 전제가 무너진다. `bot/README.md`에 열려 있던 "라운드 2에서 위인을 거치는가"라는
질문과 같은 질문을 자동으로 측정한다.

## 하지 않는 것

- **자연어가 참인지 판정하지 않는다.** 검사기 관할을 좁게 유지한다는 이 저장소의 규율을
  따른다. "이 각주가 이 문장의 근거가 맞는가"는 사람의 표본 검토가 계속 담당한다
- **산출물을 `answers/`에 쓰지 않는다.** `perf-runs/`에 쓴다. 테스트 답변이 섞이면
  `lint:answers` 지표가 오염돼 기준선의 측정 영점이 무의미해진다. 실행마다 `answers/`가
  건드려졌는지 `answers_leaked`로 확인한다
- **프로브가 실패해도 출처를 추가해 통과시키지 않는다.** 고칠 곳은 에이전트 프롬프트·게이트·
  봇 코드다. 근거를 더해 지표를 움직이는 것은 `CLAUDE.md`가 명시적으로 금지한 행위다

## 측정 중 고정

프롬프트·위키·프로브 문구는 실행 중에 고치지 않는다. 이 실행은 `e6a86cb` 시점의 행동을
재는 것이고, 측정 도중 대상을 바꾸면 결과를 해석할 수 없다. 고친 뒤에는 영향받은 프로브를
다시 돌린다 — 순서가 반대면 회귀 판정이 성립하지 않는다.
