# 에듀테크 오라클 (edtech-oracle) — 설계 명세

- 작성일: 2026-08-14
- 상태: 설계 확정 대기
- 선행 프로젝트: [edtech-pantheon](https://github.com/taehyeonglim/edtech-pantheon)

## 1. 배경과 목적

사용자가 에듀테크에 관해 질문하면, 교육공학의 위인들이 등장해 **학술적 근거에 기반해서만** 답한다.

선행 프로젝트 `edtech-pantheon`은 교육공학 36인을 시각적으로 읽는 **아카이브**다. 사람이 읽는 편집 요약이며, 근거는 문단 단위로 출처 ID에 연결되어 있다.

`edtech-oracle`은 같은 데이터를 **말하는 시스템**으로 바꾼다. 에이전트가 근거를 인용하며 답하고 토론하려면 두 가지가 더 필요하다.

1. **주장 단위 인용 추적** — 문단 단위 `sourceIds`로는 "이 문장의 근거가 무엇인가"를 답할 수 없다.
2. **근거 없음을 말할 수 있는 장치** — 근거 기반을 표방하면서 근거가 없을 때 지어내면 시스템 전체가 무너진다.

이 명세는 그 두 가지를 기계적으로 강제하는 구조를 정의한다.

## 2. 범위

### 이번 단계에 포함

- 근거 DB(Karpathy LLM Wiki 방식) 구축
- pantheon 36인 · 출처 124건 이관
- 위인 서브에이전트 38개 (위인 36 + 라우터 + 큐레이터)
- 질의(`/ask`) · 토론(`/debate`) · 수집(`/ingest`) · 검증(`/lint`)
- GitHub 공개 레포 + README

### 이번 단계에서 제외

- **디스코드 프론트엔드** — 별도 서버 구축, 라우팅 어댑터, 프로필 이미지. 이번 단계 산출물이 전부 마크다운이므로 어댑터만 얹으면 되도록 설계한다.
- 초상 이미지 권리 정리 (§10 참조)

## 3. 아키텍처 — 3계층

Karpathy의 LLM Wiki 원문([gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f))은 의도적으로 추상적이다. 고정된 것은 **3계층(raw / wiki / schema)** 과 **3오퍼레이션(ingest / query / lint)** 뿐이며, 디렉터리 구조·스키마·페이지 포맷은 도메인에 맞게 설계하도록 위임되어 있다. 아래는 이 프로젝트의 구체화다.

```
edtech-oracle/
├── CLAUDE.md                  # Layer 3 — 스키마. 위키 유지 규칙의 정본
├── raw/                       # Layer 1 — 불변 원자료   ⛔ gitignore
│   ├── papers/ books/ archives/
│   └── MANIFEST.md            # ✅ 커밋 — 원자료 목록·티어·출처 URL (본문 제외)
├── wiki/                      # Layer 2 — 에이전트가 유지하는 마크다운  ✅ 커밋
│   ├── index.md               # 카탈로그. ingest마다 갱신
│   ├── log.md                 # append-only 연대기
│   ├── router-map.md          # 개념·영역 → 위인 매핑표
│   ├── KNOWN-ISSUES.md        # 이관된 알려진 결함 추적 (§10)
│   ├── pioneers/              # 위인 36
│   ├── concepts/              # 개념 정본 (2인 이상이 공유하는 개념만)
│   ├── debates/               # 대립축
│   └── sources/               # 출처 요약
├── sources.json               # 출처 레지스트리 (티어·서지·URL·DOI)
├── .claude/
│   ├── agents/                # 38개 (스크립트 생성)
│   └── commands/              # ask · debate · ingest · lint
├── scripts/
│   ├── lint-wiki.mjs
│   ├── import-pantheon.mts
│   └── gen-agents.mjs
├── test/fixtures/             # lint 8규칙별 통과·실패 케이스
└── docs/superpowers/specs/
```

### 3.1 raw/를 커밋하지 않는 이유

논문 전문·도서 스캔을 공개 레포에 올리면 저작권 문제가 된다. 그러나 `raw/MANIFEST.md`는 커밋한다 — **원문은 없어도 "무엇을 근거로 삼았는지"는 공개**되므로 근거 추적성이 끊기지 않는다. 위키 본문은 pantheon과 동일하게 **직접 인용문이 아닌 편집 요약** 원칙을 따르고, 정확한 서지(저자·연도·페이지·DOI)를 각주로 남긴다.

`MANIFEST.md` 항목 형식:

```markdown
| id | tier | 서지 | 원문 위치 | 접근일 |
|---|---|---|---|---|
| gagne-1985 | A | Gagné, R. M. (1985). *The Conditions of Learning* (4th ed.) | raw/books/gagne-1985.md | 2026-08-14 |
```

## 4. 인용 스키마 — 프로젝트의 등뼈

"모든 말에 근거를 인용한다"를 기계 검사 가능한 형태로 내린다. **각주 ID = sourceId**로 통일한다.

```markdown
---
title: 로버트 가네
type: pioneer                      # pioneer | concept | debate | source | meta
slug: robert-gagne
sources: [gagne-1985, gagne-briggs-1974, reiser-2017]
related: ["[[concepts/nine-events]]", "[[debates/design-vs-constructivism]]"]
confidence: high                   # high | medium | low
updated: 2026-08-14
---

## 학습결과의 다섯 범주

가네는 학습 결과를 언어정보·지적기능·인지전략·태도·운동기능의
다섯 범주로 나누고, 각 범주가 서로 다른 내적·외적 조건을
요구한다고 보았다[^gagne-1985].

[^gagne-1985]: Gagné, R. M. (1985). *The Conditions of Learning* (4th ed.).
    Holt, Rinehart and Winston. pp. 47–68. — tier A · [[sources/gagne-1985]]
```

**티어를 각주에 인라인으로 표기**한다. `sources.json`을 열지 않아도 답변 텍스트만으로 근거 강도를 판별할 수 있어야 한다 — 디스코드에서 사용자가 보는 것은 답변 텍스트뿐이다.

**각주 정의는 반드시 `[[sources/<id>]]` 링크로 끝난다.** 각주(`[^id]`)는 wikilink가 아니므로, 이 링크가 없으면 출처 페이지 약 100개가 전부 고아가 되어 규칙 7에 걸린다. 이 규칙 덕에 어떤 인용에서든 출처 요약 페이지로 한 번에 이동할 수 있다.

### 4.1 출처 티어

pantheon 체계를 계승한다.

| 티어 | 정의 | 사용 제약 |
|---|---|---|
| **A** | 원저작, 당사자 기록, 원문 아카이브 | 제약 없음 |
| **B** | 피어리뷰 논문, 학술서, 학회·대학 공식 기록 | 제약 없음 |
| **C** | 백과사전, 일반 참고 자료 | **단독 근거 금지.** 탐색·교차확인용 |

"논문은 1티어"라는 요구는 원저작 → A, 피어리뷰 논문 → B로 매핑된다. pantheon 데이터와 호환을 유지하기 위해 A/B/C 문자 체계를 그대로 쓴다.

### 4.2 lint 8규칙

`scripts/lint-wiki.mjs`가 강제한다. 이것이 §8 4단계 병렬 확장의 게이트다.

규칙은 **`type`별로 적용 범위가 다르다.** `meta`(`index.md` · `log.md` · `router-map.md` · `KNOWN-ISSUES.md`)는 근거를 서술하는 페이지가 아니므로 인용 관련 규칙에서 면제된다. 면제하지 않으면 임포터가 생성한 파일에서 2단계 게이트가 곧바로 실패한다.

| # | 규칙 | 적용 대상 | 실패 예 |
|---|---|---|---|
| 1 | 프론트매터 필수 필드 존재·유효 | 전체 (필수 필드는 `type`별로 다름) | `type` 누락, 미정의 enum 값 |
| 2 | 본문의 모든 `[^id]`가 페이지 내에 정의됨 | 전체 | 정의 없는 각주 참조 |
| 3 | 모든 각주 id가 `sources.json`에 실재 | 전체 | 존재하지 않는 출처 인용 |
| 4 | 프론트매터 `sources:` ≡ 본문 각주 집합 | 전체 | 선언과 실사용 불일치 |
| 5 | 모든 `[[wikilink]]`가 실재 파일로 해석됨 | 전체 | 깨진 링크 |
| 6 | **인용 밀도** — 모든 `##` 섹션에 각주 ≥ 1 | pioneer · concept · debate | 근거 없는 서술 |
| 7 | 고아 페이지 없음 (`index.md`에서 도달 가능) | 전체 | 아무도 링크하지 않는 페이지 |
| 8 | `confidence: high`는 A/B 티어 출처 ≥ 1 | pioneer · concept · debate | C티어만으로 high 선언 |

`--strict` 플래그는 위 8규칙 전부를 오류로 처리한다. 기본 모드는 6·7을 경고로 처리해 작성 중 상태를 허용한다.

**이 lint가 병렬 외주를 성립시킨다.** 위키 작성은 본래 게이트가 없는 콘텐츠 작업이라 병렬 위임에 부적합하다. lint를 **먼저** 만들어 두면 `tsc --noEmit`과 동급의 강한 게이트가 되어 33명분 병렬 생성이 검증 가능해진다. 순서를 바꾸면 검증 없는 대량 생성이 된다.

## 5. 위키 조직 축

4분할한다.

| 디렉터리 | 역할 | 생성 규칙 | 초기 개수 |
|---|---|---|---|
| `pioneers/` | 위인의 정체성과 **자기 입장** | pantheon 36인 | 36 |
| `concepts/` | 개념 정본 | 유기적 성장 (§5.1) | 3 → 증가 |
| `debates/` | 대립축 | `relationships` 중 `layer: "comparison"` | 34 |
| `sources/` | 출처 요약 | 위키가 실제 인용하는 출처만 | ≤124 |

위인 페이지는 개념 정의를 쓰지 않고 `[[concepts/cognitive-load]]`로 링크한 뒤 **그 개념에 대한 자기 입장만** 쓴다. Sweller와 Mayer가 인지부하를 공유해도 정의는 한 곳에만 존재하므로, 두 페이지가 서로 모순되는 정의를 갖는 사태를 구조로 차단한다.

### 5.1 concepts/는 유기적으로 자란다

**pantheon에는 통제 어휘가 없다.** 실측 결과 `concepts[]` 고유값 141개 중 2인 이상이 공유하는 것은 **3개**뿐이고(교수기계 · 수행 격차 · 실천공동체), `domains` · `school` · `era`도 대부분 1인 전용이다. 전부 페이지로 만들면 고아 스텁 138개가 생기고(규칙 7 위반), 기계적 공유 추출만 쓰면 개념 계층이 3개로 붕괴한다.

따라서 3단계로 자란다.

1. **이관** — 기계적으로 공유되는 3개만 생성
2. **파일럿** — 가네 · 파퍼트 · 메이어가 실제로 필요로 하는 개념만 근거와 함께 생성
3. **확장** — codex는 **이미 존재하는 개념 페이지에만 링크**한다. 새 개념은 프론트매터 `proposed_concepts: [...]`로 **제안만** 하고 링크하지 않는다. Claude가 검토해 승인한 것만 페이지로 만든다.

3단계의 제약이 핵심이다. codex가 자유롭게 개념 페이지를 만들면 33인 × 평균 4개 = 130여 개의 중복·날조 개념이 생긴다. 링크를 금지하면 규칙 5(깨진 링크)에도 걸리지 않는다.

교육공학의 실제 쟁점 지도는 `debates/` 34개가 이미 담고 있다 — `clark-kozma 매체 효과 논쟁`, `papert-mayer 만들며 배우기 vs. 설명을 통한 학습` 등 전부 라벨과 `sourceIds`를 갖추고 있다. 개념 계층이 얇게 출발해도 토론 기능은 1일차부터 동작한다.

## 6. 시대 격차 — 3마커 체계

사용자 질문은 대부분 현대 에듀테크(생성형 AI, LMS, 마이크로러닝)인데 위인들은 1900~2000년대 인물이다. "모든 말에 근거를 인용"을 곧이곧대로 지키면 대부분의 질문에 답할 수 없고, 느슨하게 풀면 근거 없는 창작이 된다.

답변에 **세 종류 마커를 강제**한다.

```
[근거]     문헌에 직접 있는 주장. 각주 필수.
[적용]     위인의 원리를 현대 상황에 적용한 추론.
           출발점이 된 원리의 각주 필수 + 추론임을 명시.
[근거없음] 해당 위인의 문헌에 근거가 없음. 회피가 아니라 정직성 장치.
```

예시:

```
[근거] 나는 학습 결과를 다섯 범주로 나누었고, 각 범주는 서로 다른
       내적·외적 조건을 요구한다[^gagne-1985].

[적용] 생성형 AI 튜터는 내 시대에 없었다. 다만 위 원리를 적용하면
       "지적 기능"을 가르치는 AI와 "태도"를 다루는 AI는 서로 다른
       사태 설계를 요구할 것이다 — 이는 내 문헌의 직접 주장이 아니라
       원리로부터의 추론이다.

[근거없음] 협력학습의 적정 집단 규모에 대해서는 내 저작에 근거가 없다.
```

`[근거없음]`이 없으면 위인들은 그럴듯하게 지어낸다. 이 마커는 선택이 아니라 시스템 요구사항이다.

## 7. 에이전트 구조

프로젝트 로컬 `.claude/agents/` 플랫 구성. 총 38개 = 위인 36 + `router` + `curator`.

```markdown
---
name: gagne
description: 로버트 가네 — 학습조건, 9가지 수업사태, 학습결과 5범주.
  수업설계·과제분석·계열화 질문에 호출.
model: sonnet
tools: Read, Grep, Glob
---
```

### 7.1 쓰기 권한 박탈

위인 에이전트는 `Read, Grep, Glob`만 갖는다. 위인이 위키를 고칠 수 있으면 답변하다가 근거 DB를 오염시킨다. 위키 수정 권한은 **`curator` 하나**만 가지며 `/ingest` 경로로만 진입한다. 근거 DB의 무결성이 답변 편의보다 우선한다.

### 7.2 컨텍스트 경계 — 독립성의 실체

각 위인은 `wiki/pioneers/<자기slug>.md`와 **거기서 링크된** `concepts/` · `debates/` · `sources/`만 읽는다. **다른 위인 페이지는 읽지 않는다.** 파일 접근이 갈려 있어야 서로의 논리를 표절하지 않고 각자의 근거에서 말한다.

토론에서 상대 발언을 봐야 할 때는 **오케스트레이터가 프롬프트로 주입**한다. 위키를 통해 새어 들어가지 않는다.

### 7.3 시스템 프롬프트 6블록

1. **정체성** — 생몰년, 소속, 핵심 명제, 대표 저작
2. **컨텍스트 경계** — 읽을 수 있는 파일 목록 (7.2)
3. **3마커 규칙** — §6
4. **각주 규칙** — `[근거]`·`[적용]`은 각주 필수, 각주 형식 §4
5. **목소리** — 1인칭, 시대 어투, 과장 금지, 자기 한계 인정
6. **되묻기 권한** — 질문이 모호하면 답변 대신 `NEEDS_CLARIFICATION: <질문>` 반환

### 7.4 에이전트는 손으로 쓰지 않는다

`scripts/gen-agents.mjs`가 `wiki/pioneers/*.md`의 프론트매터를 읽어 **위인 36개를 생성**한다. `router`와 `curator`는 위인 페이지에서 파생되지 않으므로 정적 템플릿으로 따로 관리한다 (36 생성 + 2 정적 = 38).

위키가 정본이고 위인 에이전트는 파생물이므로, 근거가 갱신되면 재생성만으로 동기화가 끝난다. 36개를 손으로 관리하면 반드시 어긋난다.

`description` 필드는 예산 항목이다. 36개 description이 매 세션 시스템 프롬프트에 실린다(약 1,000토큰 상시 점유). description에는 **"언제 이 위인을 부르는가"만** 압축해 쓰고 전기는 넣지 않는다.

## 8. 기능

### 8.1 `/ask` — 질의

```
질문 → router 에이전트 (wiki/router-map.md 참조, 위인 1~3명 선정)
     → 선정 위인 병렬 호출 (단일 메시지 다중 Agent 호출)
     → 각자 자기 근거로 답변 (각주 + 3마커)
     → 메인 세션이 나열 출력
```

메인 세션은 위인 발언을 **요약하지 않는다.** 요약하는 순간 각주가 끊기고 "누가 무엇을 근거로 말했나"가 뭉개진다. 메인 세션은 순서 배치와 사회(司會)만 한다.

위인이 `NEEDS_CLARIFICATION`을 반환하면 메인 세션이 AskUserQuestion으로 사용자에게 전달한다.

### 8.2 `/debate` — 토론

토론 진행자는 별도 에이전트가 아니라 **`/debate` 슬래시 커맨드를 실행하는 메인 세션**이다. 참가자 발언을 프롬프트로 주입하고 라운드를 관리하는 일은 대화 상태를 들고 있어야 하므로 서브에이전트로 격리하면 오히려 손해다.

```
주제 → 메인 세션: debates/에서 대립축 탐색 → 참가자 2~4명 선정
라운드 1  입장 표명 — 참가자 병렬 호출, 서로 안 보임
     ↓  사용자에게 출력 + 선택지 제시
라운드 2  반박 — 상대 발언을 프롬프트로 주입, 순차 호출
     ↓  사용자 개입 (계속 / 특정 위인 파고들기 / 종료)
라운드 3  쟁점 정리 — 합의점과 미해결 대립축 명시
```

**라운드 1이 병렬인 이유**: 순차로 돌리면 뒷사람이 앞사람 말에 맞춰 조정한다(anchoring). 독립적으로 내야 진짜 대립축이 드러난다. 라운드 2부터는 반박이 목적이므로 순차다.

**억지 합의로 끝내지 않는다.** 라운드 3은 "여기까지는 같고, 여기서부터는 문헌상 화해되지 않는다"로 끝낸다. Clark–Kozma 미디어 논쟁을 비롯한 교육공학의 실제 논쟁은 실제로 미해결이다.

### 8.3 `/ingest` — 수집

```
raw/에 자료 투입
  → curator: 티어 판정 → sources.json 등재
  → wiki/sources/<id>.md 요약 생성
  → 영향받는 pioneers/ · concepts/ 갱신
  → index.md · log.md 갱신
  → lint --strict 실행 → 실패 시 롤백
```

### 8.4 `/lint` — 검증

§4.2의 8규칙 + 위키 건강검진(모순 주장 탐지, 미생성 개념 링크, 오래된 페이지).

|---|---|---|---|
| 0 | 스캐폴드 · `git init` · `gh repo create` · `CLAUDE.md` 스키마 | Claude | 구조 생성 확인 |

| 3 | **파일럿 3인 심화** + 에이전트 템플릿 확정 | Claude | `lint --strict` + 질의·토론 수동 검증 |

**1단계 lint가 4단계보다 먼저여야 한다** — 게이트가 없으면 병렬 확장은 검증 없는 대량 생성이다. 이 순서는 바꿀 수 없다.

### 9.1 이관 방식

`scripts/import-pantheon.mts`는 `tsx`로 실행하며 pantheon의 `src/data/*.ts`를 직접 import한다(경로는 `PANTHEON_PATH`, 기본 `../edtech-pantheon`).

**Node 기본 타입 스트리핑으로는 안 된다** — pantheon 모듈이 `import { expandedPioneers } from "./pioneers-expansion"`처럼 확장자 없는 값 import를 쓰는데 Node ESM은 확장자를 요구한다. `tsx`는 이를 해석한다. 실측 검증 완료(2026-08-14): `pioneers 36 · sources 124 · relationships 54 · biographies 36` 정상 로드.

산출:

| 산출물 | 개수 | 원천 |
|---|---|---|
| `wiki/pioneers/*.md` | 36 | `pioneers` + `biographies` — `sections[]`·전기 → `##` 섹션, `sourceIds` → 각주 |
| `sources.json` | 124 | `sources` 그대로 (tier 포함) |
| `wiki/sources/*.md` | ≤124 | 위키가 실제 인용하는 id만. 미인용 id는 경고 출력 |
| `wiki/debates/*.md` | 34 | `relationships` 중 `layer: "comparison"` |
| `wiki/concepts/*.md` | 3 | 2인 이상 공유 개념 (§5.1) |
| `wiki/router-map.md` | 1 | `domains` · `concepts` · `debates` → 위인 매핑 |
| `wiki/index.md` · `log.md` · `KNOWN-ISSUES.md` | 3 | `type: meta` |

### 9.2 파일럿 3인

**가네 · 파퍼트 · 메이어.** 체계적 수업설계 / 구성주의 / 실증 인지가 정면으로 갈리므로 3단계에서 토론 기능까지 실검증된다. pantheon 자료도 셋 다 풍부하다.

### 9.3 4단계 병렬 실행

pumasi 스킬 대신 **`codex exec -m gpt-5.6-luna`를 직접 호출**한다. 33인을 6~8개 배치로 묶고, 각 배치는 3단계에서 확정된 템플릿과 lint 규칙을 지시서로 받는다. 배치 완료마다 `node scripts/lint-wiki.mjs --strict`로 검증하고 실패분만 재실행한다.

모델 검증 완료: `codex exec -m gpt-5.6-luna` → `LUNA_OK` 정상 반환 (2026-08-14).

## 10. 알려진 이슈 — 그대로 가져오되 그대로 믿지 않는다

pantheon README가 자기 P1 이슈를 공개하고 있다.

1. **Ann L. Brown / John Seely Brown 혼동** — `brown-collins` 관계 서술이 잘못된 저자에 귀속됨
2. **관계 근거의 추적성 부족** — 내부 ID만 표시되고 원문 링크·페이지·DOI 미반영
3. **초상 권리** — 36장 중 명확한 것은 14장
4. **서지·연표의 직접 근거 부족** — 일부 연도·제목이 DOI 메타데이터와 불일치
5. **전기의 C티어 의존** — 다수 인물 생애 서술이 Wikipedia 기반

데이터는 스펙대로 **그대로 이관하되**, 위 목록을 `wiki/KNOWN-ISSUES.md`로 함께 들여오고 영향받는 페이지에 `confidence: low`를 부여한다. 오라클은 근거를 인용해 말하는 시스템이므로, 알려진 오류를 무표시로 물려받으면 그대로 "근거 있는 주장"으로 출력된다.

C티어 근거는 각주에 `— tier C` 가 인라인 표기되므로 답변 텍스트만 봐도 강도가 드러난다(§4). 별도 마커는 두지 않는다.

**초상**: 디스코드 단계에서 프로필 이미지 36장이 전원 필요하다. 권리 미확정 22장은 pantheon 자신의 권고대로 이니셜 대체 이미지를 쓴다. 이번 단계 범위가 아니며 기록만 남긴다.

| 대상 | 방법 |

| lint 스크립트 | `test/fixtures/`에 규칙별 통과·실패 케이스를 두고 8규칙 각각의 검출 확인 |
