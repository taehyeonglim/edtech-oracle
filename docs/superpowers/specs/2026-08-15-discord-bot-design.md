# 디스코드 봇 — 설계 명세

**날짜** 2026-08-15
**상태** 구현됨 (2026-08-15). 실전 실행 미검증
**전제** 맥미니 24시간 가동 · 구독제 Claude Code · **단일 사용자(본인) 전용**

## 무엇을 만드는가

에듀테크 오라클의 대화 프론트엔드. 디스코드 슬래시 커맨드를 받아 **Claude Code를
헤드리스(`claude -p`)로 실행**하고, 위인들이 각자의 이름·아바타를 달고 채널에 등장한다.

## 왜 오케스트레이터를 새로 쓰지 않는가

README는 "`/debate`의 라운드 상태머신과 `NEEDS_CLARIFICATION` 왕복이 Claude Code 세션의
대화 상태에 얹혀 있어서, 옮기려면 오케스트레이터를 새로 써야 한다"고 진단했다.

**세션을 옮기지 않고 그 자리에서 돌리면 새로 쓸 것이 없다.** 맥미니가 항상 켜져 있으므로
봇이 저장소 안에서 `claude -p`를 실행하면 다음이 전부 그대로 작동한다.

| 자산 | 상태 |
|---|---|
| `.claude/commands/ask.md` · `debate.md` | 그대로 |
| `.claude/agents/*.md` 36개 | 그대로 |
| 위키 파일 접근 | 저장소 안에서 도니 그대로 |
| 답변 게이트(`answers/` + `lint:answers`) | 같은 디렉터리라 그대로 |

Claude API로 다시 구현하는 경로(프롬프트 사전 적재, 라우터 structured output, 프롬프트 캐싱)는
**채택하지 않는다.** 구독제로 이미 도는 것을 유료 API로 옮길 이유가 없다.

## 검증된 전제

설계가 이 다섯 가지에 의존한다. 전부 실측했다.

| 전제 | 검증 |
|---|---|
| `-p`에서 프로젝트 슬래시 커맨드가 확장된다 | `claude -p "/lint"` → 15턴·212초 완주, bash + 서브에이전트 표본 검토까지 |
| `session_id`를 돌려준다 | `--output-format json`의 `session_id` 필드 |
| `--resume`이 컨텍스트를 복원한다 | 1차 "사과" → `--resume` 2차 "방금 말한 단어?" → "사과", session_id 동일 |
| 되묻기를 막을 수단이 있다 | `--disallowedTools AskUserQuestion` |
| 라운드 제어를 주입할 수단이 있다 | `--append-system-prompt` |
| 무인 실행에서 파일을 쓸 수 있다 | `--permission-mode acceptEdits`. **`dontAsk`는 Write를 거부한다**(아래) |

`--forward-subagent-text`는 쓰지 않는다. 화자 구분은 `answers/` 파일이 확정해 준다.

### 권한 모드는 `acceptEdits`다

초안은 `dontAsk`였다. 실제로 돌려 보니 **Bash는 통과하고 Write가 거부된다** — 봇이 답변
파일을 한 건도 저장하지 못한 채 "저장에 실패했습니다"라는 산문만 게시했을 것이다.
`acceptEdits`는 Write·Bash 모두 통과한다(2026-08-15 실측). `bypassPermissions`는 전부
허용하지만 무인 실행에 그만한 권한을 줄 이유가 없다.

## 사용 범위 — 단일 사용자

구독제는 개인 사용 기준이다. 본인만 쓰는 비공개 서버이므로 개인 사용의 연장이며,
따라서 다음이 **설계에서 빠진다**: 동시 요청 큐, 레이트리밋 폴백, 비용 상한,
다중 사용자 인증, 남용 방지.

레이트리밋에 걸리면 폴백 없이 그냥 막힌다. 개인용이므로 감수한다.

## 구조

```
bot/                      새 디렉터리 · 자체 package.json
  index.mjs               디스코드 클라이언트 · 슬래시 커맨드 등록 · 락
  run-claude.mjs          claude -p 실행 · session_id 보관
  render.mjs              answers/*.md → 웹훅 페이로드 (순수 함수)
  config.json             길드·본인 사용자 ID·웹훅 URL·사이트 base URL (커밋 안 함)
  config.example.json     위 파일의 빈 서식
```

**`bot/`에 자체 `package.json`을 둔다.** 루트는 README가 "런타임 의존성 0"이라고 공언한
상태인데 봇은 `discord.js`를 끌고 온다. 분리하면 그 성질이 유지되고, 더 중요하게는
**위키·게이트 도구가 봇 없이도 그대로 돈다** — 사이트 빌드와 lint는 봇의 존재를 몰라야 한다.

`render.mjs`는 순수 함수다. `answers/<파일>.md`와 이미 올린 섹션 수를 받아 페이로드 배열을
돌려준다. 디스코드도 파일시스템도 모른다 — `check-answer.mjs`가 순수 검사기인 것과 같은 방식이고,
그래야 단위 테스트가 된다.

## 답변 파일이 유일한 인터페이스

봇은 `claude -p`의 stdout을 파싱하지 않고 **`answers/<파일>.md`를 읽는다.** 이유 셋:

1. `## <slug>` 화자 구분이 확정돼 있다
2. 각주 id가 그대로라 사이트 URL로 바꾸기 쉽다
3. **이미 답변 게이트를 통과한 산출물**이다

`render.mjs(파일, 이미올린섹션수)`가 델타만 돌려준다. 화자 이름이 아니라 **섹션 인덱스**로
자른다 — `/debate`는 같은 위인이 라운드마다 반복 등장하기 때문이다.

이 설계로 `/ask`와 `/debate`가 같은 코드 경로가 된다. 둘 다 "claude 실행 → 파일 읽기 →
새 섹션 게시"이고, `/ask`는 라운드가 하나뿐인 경우일 뿐이다.

## 흐름

### `/ask <질문>`

```
reply("시작했다")                   3초 안에. 최종 출력은 이 토큰에 걸지 않는다
claude -p "/ask <질문>" --output-format json
  --disallowedTools AskUserQuestion --permission-mode acceptEdits
새로 생긴 answers/*.md 찾기
render.mjs로 화자별 페이로드 변환
웹훅으로 순서대로 게시 + 검사 요약 한 줄
```

### `/debate <주제>`

```
라운드1  claude -p "/debate <주제>"
           --append-system-prompt "이번 호출은 라운드 1까지만. 되묻지 않는다.
                                   결과를 answers/ 파일에 즉시 쓴다."
           --disallowedTools AskUserQuestion
         → session_id 보관 → 새 섹션 게시 → [계속] [종료] 버튼

라운드2  claude -p --resume <sid> "라운드 2(반박)를 진행하고 파일에 이어 쓴다."
라운드3  claude -p --resume <sid> "라운드 3(쟁점 정리)를 진행하고 파일에 이어 쓴다."
```

`debate.md`는 **고치지 않는다.** 라운드 제어는 `--append-system-prompt`로 주입하고,
원래 설계 의도였던 라운드 사이 개입(계속·파고들기·종료)은 디스코드 버튼이 대신한다.

**라운드는 기다렸다 자동으로 넘어간다**(기본 90초, `debateAutoMs`). 버튼을 눌러야만
진행하면 자리를 비운 사이 토론이 멈춰 서 있는다 — 단일 사용자 설계에서 그 정지는 지킬
사람이 없는 관문이다. 그래서 버튼의 뜻이 바뀐다: "지금 진행"은 시계를 앞당기고,
"종료"가 흐름을 멈추는 쪽이 된다. 값이 "포기하기 전 유예"가 아니라 "끼어들 틈"이므로
길게 잡을 이유가 없다.

## 출력

웹훅으로 위인마다 이름·아바타를 달아 **2,000자씩 나눠** 게시한다. 실측 답변이 화자당
2,600자였으므로 화자마다 2개 메시지, 3인 답변이면 총 7개.

**인터랙션 토큰에 최종 출력을 걸지 않는다.** `/lint`가 212초였고 `/debate` 3라운드는
10분을 넘길 수 있는데 디스코드 지연 응답은 15분에 만료된다. 인터랙션에는 즉시
"시작했습니다"만 답하고 실제 출력은 전부 웹훅으로 보낸다. 아바타 때문에 어차피 웹훅을
쓰므로 추가 비용이 없다.

**각주 변환** — `[^gagne-1965]` → `[A1](https://…/sources/gagne-1965.html)`.
base URL은 `config.json`에 둔다. `scripts/site/urls.mjs`는 의도적으로 상대경로 전용이라
("base path 설정·`<base>` 태그·빌드 환경변수가 전부 불필요해진다") 재사용할 수 없다.

라벨은 **티어 문자 + 섹션 안 등장 순서**다. 초안은 위첨자(`[1ᴬ]`)였으나 유니코드에
**위첨자 대문자 C가 없어** A·B만 위첨자가 되고 C는 소문자 `ᶜ`로 떨어진다 — 티어 표기가
서로 다른 크기로 렌더되므로 버렸다. 번호는 섹션마다 1부터 다시 센다. `/debate`는 같은
위인이 라운드마다 다시 등장하므로 파일 전역 번호는 읽는 사람에게 의미가 없다.

**서지 범례** — 각 화자의 마지막 메시지 끝에 `-# `(디스코드 작은 글씨)로 인용한 출처를
저자·연도·제목까지 적는다. 대화 표면에서 근거를 지우면 이 프로젝트의 주장이 무너진다.
범례는 **본문과 같은 분할기를 통과한다** — 나중에 이어 붙이면 마지막 조각이 한도 근처일 때
정확히 경계에서 넘친다. 한도는 2,000이 아니라 **1,900**을 쓴다. 경계에서 디스코드의
글자 세는 방식과 다투지 않으려는 여유다.

## 화자별 증분 게시

**실측(2026-08-16).** 라우터 64초 → 위인 3명 병렬 실행, 각각 2:09·2:47·2:54에 종료 →
답변 파일 작성 4:21 → 게이트 4:24 → 종료 5:33. 먼저 끝난 위인의 발언이 **3분 24초** 동안
묶여 있었다.

오케스트레이터가 한 명씩 파일에 이어 쓰는 경로는 **없다.** 위인들이 단일 메시지에서
병렬 호출되므로 오케스트레이터는 셋이 모두 끝난 뒤에야 제어를 되찾는다. 순차 호출로
바꾸면 가능하지만, 병렬은 위인이 서로의 답을 볼 수 없게 만드는 구조적 장치라 버리지 않는다.

**대신 봇이 스트림에서 발언을 받아 직접 검사한다.**

```
--output-format stream-json
  최상위 tool_use:Agent   → id와 subagent_type(=위인 slug)
  같은 id의 tool_result   → 그 위인이 끝나는 즉시 최종 발언 도착
```

`--forward-subagent-text`는 여전히 쓰지 않는다. 서브에이전트 **내부** 메시지를 흘려주는
플래그인데 우리가 필요한 최종 반환값은 그것 없이도 최상위로 온다.

받은 발언은 화자 하나짜리 답변 파일로 만들어 `check-answer.mjs`에 넣는다. 검사기가 순수
함수라 가능한 일이고, 규칙 3(인용 범위)은 원래 화자별 검사라 쪼개도 의미가 그대로다.

**위조급이 남은 발언은 게시하지 않는다.** 오케스트레이터가 그 위인을 1회 재호출해 고치고,
봇은 마지막에 답변 파일에서 고쳐진 판을 읽어 올린다. 검사를 통과하지 않은 인용이 채널에
먼저 나가는 일은 없다 — 그것이 이 프로젝트의 존재 이유다.

마지막 정산에서 이미 올린 발언은 다시 올리지 않되, **본문이 바뀐 발언은 정정으로 다시**
올린다. 틀린 인용이 채널에 남아 있으면 게이트가 잡아 준 의미가 사라진다.
비교 키는 `<slug>#<그 화자의 몇 번째 발언인가>`이며, 순번은 게이트 통과 여부와 무관하게
센다 — 건너뛴 발언이 순번을 비우면 정산이 한 칸씩 어긋난다.

## 실패 처리

| 상황 | 처리 |
|---|---|
| `is_error: true` 또는 비정상 종료 | 오류를 채널에 그대로 게시. 조용히 죽지 않는다 |
| 구독 레이트리밋 | CLI 메시지를 그대로 전달. 폴백 없음 |
| 답변 파일이 안 생김 | JSON `result`를 원문 그대로 게시하고 "파일이 없어 원문을 올립니다"를 명시 |
| 이어 쓸 라운드에 **새 파일**이 생김 | 커서를 버리고 새 파일을 처음부터 읽는다. 앞 파일의 섹션 수를 적용하면 라운드가 통째로 비어 올라오지 않는다 |
| 파일은 있는데 **새 섹션이 없음** | 위와 같은 실패로 다룬다. 원문을 게시한다 — 조용히 넘어가면 몇 분 기다린 끝에 요약 한 줄만 남는다 |
| 위조급 위반 잔존 | `/ask`가 이미 1회 재호출하고 명시한다. 봇은 검사 요약 줄을 함께 게시 |
| 동시 실행 | 락 하나. 두 번째 요청은 "진행 중입니다"로 거절 — 같은 작업 트리에 두 프로세스가 쓰면 깨진다. 락은 검사 직후 **동기적으로** 잡는다. 사이에 `await`가 있으면 그 왕복 동안 두 번째 요청이 검사를 똑같이 통과한다 |

## 답변 커밋 정책

봇이 **커밋만 하고 푸시하지 않는다.**

작업 트리가 깨끗하게 유지되고, 게이트는 다음에 사람이 직접 푸시할 때 CI가 잡는다.
질문 하나에 사이트를 재배포하는 것은 과하다.

## 범위 밖

- **초상 권리 22장** — 비공개 개인 서버라 위험도가 낮아지지만 이미지가 디스코드 서버에
  업로드되는 것은 여전하다. `KNOWN-ISSUES` #3은 유효하며 이니셜 대체가 기본이다
- **Claude API 재구현** — 채택하지 않음(위 참조)
- **다중 사용자 운영** — 공개 서버로 바꾸려면 사용 범위부터 다시 판단해야 한다
- **`/ingest`·`/lint`의 디스코드 노출** — 위키 쓰기 경로라 채팅에서 부르지 않는다
- **공식 `discord` 플러그인** — 채택하지 않음(아래)

### 공식 플러그인을 쓰지 않는 이유

`claude-plugins-official`의 `discord` 플러그인(0.0.4)은 **방향이 반대다.** 디스코드 메시지를
돌고 있는 Claude Code 세션 안으로 밀어 넣는 MCP 채널이고, 도구는 넷뿐이다 —
`reply` · `react` · `edit_message` · `fetch_messages`.

`reply`의 스키마가 `chat_id · text · reply_to · files`다. **username도 avatar도 없다.**
봇 하나의 정체성으로만 말한다. 그런데 이 프로젝트가 디스코드를 고른 이유가 "위인들이 각자의
이름과 얼굴을 달고 등장한다"이고, 그것을 할 수 있는 메커니즘은 웹훅뿐이다. 세 위인이 같은
봇 이름으로 말하면 답변이 한 덩어리 텍스트가 되어 `## <slug>` 화자 구분을 세운 의미가 사라진다.

플러그인을 입력 표면으로만 쓰고 출력을 웹훅으로 보내는 하이브리드도 검토했다(`index.mjs`·
`run-claude.mjs` 약 400줄과 `discord.js`가 사라진다). 두 가지를 잃어서 접었다 —
**질문마다 새 컨텍스트로 시작하는 성질**(상시 세션 하나가 모든 대화를 누적하면 위인 격리가
세션 컨텍스트 오염에 노출된다)과, 채널로 들어온 `/ask`가 프로젝트 슬래시 커맨드로
확장되는지의 불확실성(확장되지 않으면 답변 게이트 경로가 끊긴다).

플러그인을 저장소 운영 잡담용으로 따로 설치하는 것은 이 결정과 무관하며 언제든 가능하다.
