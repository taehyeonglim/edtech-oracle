# 근거 위키 열람 사이트

## Context

`edtech-oracle`의 핵심 주장은 **"모든 말에 근거를 인용한다"**이고, 그 주장은 각주 정의가 반드시 `— tier <A|B|C> · [[sources/<id>]]`로 끝난다는 규약으로 구현되어 있다.

**문제: 이 규약이 GitHub에서 검증 불가능하다.** `[[sources/gagne-1965]]`는 GitHub 마크다운 렌더러에서 죽은 텍스트다. 실측하면 위키링크 905개 중 **509개(56%)가 각주 정의 안의 출처 링크**인데, 이게 전부 클릭되지 않는다. 게다가 `wiki/sources/` 140개 페이지는 `related` 프론트매터가 **0개**라, 들어가는 길이 각주뿐이고 나오는 길이 아예 없는 막다른 골목이다.

즉 지금은 "근거를 인용한다"고 말하면서 **근거를 따라갈 수단을 제공하지 않는다.** 이 사이트의 존재 이유는 그것뿐이다 — 본문 → 각주 → 출처 → 인용처의 왕복 경로를 닫는 것.

선행 프로젝트 `edtech-pantheon`과 중복되지 않는다. pantheon은 콘텐츠를 읽는 아카이브이고, 이 사이트는 **인용 그래프를 항해 가능하게 만드는 것**이다.

---

## 접근: 정적 다중 페이지(MPA) 생성기

SPA를 기각한다. 한국어 콘텐츠인데 해시 라우팅은 **색인 가능한 URL이 213개가 아니라 1개**가 되어 네이버 유입이 사실상 0이 되고, JS 없으면 백지가 되며, `document.title`·포커스·`aria-live`를 손으로 져야 한다. 근거 아카이브가 JS 의존이 되는 건 성격이 안 맞는다. (SPA 설계안도 결국 완화책으로 "정적 스텁 213개"를 제안했는데, 그건 MPA다.)

**런타임 의존성은 계속 0.** `markdown-it` + `markdown-it-footnote`만 devDependency로 추가한다 — `gray-matter`와 같은 빌드 타임 위치다. 마크다운 렌더러를 손으로 짜지 않는 이유는 각주 backref(한 각주가 한 페이지에서 최대 18회 참조됨)와 코드스팬 보호가 미끄럽기 때문이고, markdown-it을 고른 이유는 **각주를 공식 지원하는 유일한 후보**이며 위키링크를 `md.inline.ruler.before('link', …)`로 등록하면 `` `[[x]]` ``·`\[\[x]]` 보호가 공짜로 따라오기 때문이다.

**URL은 전부 상대경로.** `https://taehyeonglim.github.io/edtech-oracle/` 아래 뜨는데, 상대경로면 base path 설정·`<base>` 태그·환경변수가 통째로 불필요하고 `file://`에서도 열린다.

**재사용 (수정 금지):**
- `scripts/wiki-parse.mjs` — `loadPages()`, `footnoteDefs()`, `footnoteRefs()`, `stripFootnoteDefs()`, `sections()`, `asDateString()`. **파싱을 재구현하지 않는다.** lint와 사이트가 다른 진실을 갖는 게 이 프로젝트에서 가장 비싼 실수다. 위키링크 렌더는 `wikilinks()`를 쓰지 않고 markdown-it 인라인 규칙이 원문을 직접 판다(별칭 보존 필요) — 따라서 `wiki-parse.mjs`는 무손상
- `scripts/lint-wiki.mjs` — `lintWiki({wikiDir, sourcesPath, strict:true})`를 빌드 0단계 게이트로 import. **Phase 0~4 동안 무수정** (8규칙과 그 테스트의 안정성이 게이트 신뢰의 기반)
- `test/helpers.mjs` — `makeWiki()`/`page()` 재사용

## 빌드 파이프라인

```
0. 게이트     lintWiki(strict) → 오류 시 exit 1. 우회 플래그 없음
              규칙 5 통과 = 이후 모든 [[…]]가 실재한다고 가정 가능
1. 수집       collect() → SiteModel (역참조·패싯·엣지)
2. 어서션     디렉터리 화이트리스트(T12) · 파일명 ASCII · 정의줄 형식
              · 티어 일치(T2) · debate.related 길이 2(T7) → 위반 시 중단
3. 렌더       renderAll(model) → Map<경로, 문자열>  ※ 순수 함수, FS 접근 0
4. 링크검사   모든 내부 href/src가 산출물 키에 존재 → 사이트판 규칙 5
5. 쓰기       writeAll() + web/assets 복사  ※ 유일한 부작용 지점
```

3·5단계 분리가 테스트 전략의 핵심이다. 220페이지를 파일 없이 문자열로 검사할 수 있고, 4단계가 빌드 내장 회귀 방어선이 된다.

## 기능별 구현 요점

**각주·티어 (T1·T2·T4)** — `footnote_ref`/`footnote_open`/`footnote_anchor`/`footnote_block_*` 5개 렌더러 규칙 오버라이드. 티어는 `sources.json` 조회로 얻고(텍스트 파싱 아님), 꼬리의 `— tier A · [[…]]`는 **지우지 않는다** — 뱃지는 덧붙이는 것이지 대체가 아니다. 각주 정의 안의 `[[sources/x]]`는 정의 본문이 인라인 파이프라인을 타므로 자동 처리되지만 테스트로 고정한다.

**위키링크** — `md.inline.ruler.before('link', 'wikilink', …)`. 별칭 없으면 **대상 페이지의 `title`로 치환**한다(`[[pioneers/robert-gagne]]` → "로버트 가녜"). GitHub 대비 가장 큰 체감 개선. 별칭은 현재 0건이라 테스트가 유일한 방어선.

**역참조** — `footnoteDefs()` 역인덱스, 자기인용 제외(T3), 페이지당 1행 + 참조 횟수 뱃지. 실측 분포: 140/140이 ≥1, 중앙값 2, 최대 13(`mayer-2005`).

**브라우즈·필터** — 1차 축은 **역할 패싯**(T5로 분리, 빈도순 상위 12개 칩). 개념은 드롭다운이 아니라 자유 입력 태그 필터 + 공유 개념 3개 상단 고정. `confidence`는 위인 전원 high라 정보량 0이므로 출처 페이지에서만 필터로 쓴다(125 high / 15 low).

**검색** — 인버티드 인덱스를 만들지 않는다. 217문서 선형 `includes()` 스캔(1~3ms). 한국어 교착어에서 부분 문자열이 오히려 정확하다("구성주의"로 "구성주의적"이 잡힌다). **NFC 정규화 필수** — 색인·질의 양쪽. 검색 코퍼스에서 각주 정의뿐 아니라 **참조 마커 `[^…]`도 제거**해야 스니펫이 깨지지 않는다.

**그래프** — 빌드 타임 Fruchterman–Reingold → 정적 SVG. 난수 없이 id 사전순 원형 초기화로 **결정적**(같은 입력 → 바이트 동일). union-find로 컴포넌트 분할 후 패킹, 고립 6명은 하단 스트립. 노드·엣지 모두 `<a>`. 런타임 시각화 라이브러리 0. SVG 아래 34개 대립축을 `<ul>` 링크로도 렌더(스크린리더 대체 경로).

| 각주 id == 정의줄 링크 타깃 | 509/509 |
| 정의줄 tier == `sources.json` tier | 509/509 |
| `debate.related` 길이 == 2 | 34/34 |

**테스트** (`node --test`, 기존 24개 + 약 45개):
- **모든 내부 `href`/`src`가 산출물 키에 존재** — 220페이지 URL 생성 버그를 한 번에 잡는다
- **출처 링크 총수 == 509** — T1 방어. 위 테스트로는 안 잡힌다
- 같은 각주 3회 참조 → `#fnref-a-0/1/2` 3개 (T4)
- `` `[[x]]` `` → 링크 아님 / `\[\[x]]` → 이스케이프
- `roleAtoms('교육공학자 · 미디어·ICT 정책 연구자').length === 2` (T5)
- 출처 페이지 자기인용 제외 (T3)
- `s15327809jls0303_3`이 `<em>`으로 변하지 않음 (T8)
- `layout()` 2회 호출 결과 동일 (결정성)
- NFD 저장된 '가녜'를 NFC 질의로 검색 성공
- 렌더 HTML에 `undefined`/`null`/`[object Object]`/`[[`/`[^` 잔재 0회 (T10)
- **음성 테스트**: 정의줄이 깨진 픽스처 → 빌드 실패. lint 오류 위키 → 빌드 실패

음성 테스트가 중요하다. 나머지가 전부 "지금 초록이니 계속 초록"이라, 실패를 만들어낼 수 있는지 확인하지 않으면 아무것도 검사하지 않는 테스트가 된다.

## 구현 결과 (2026-08-14)

계획과 달라진 것만 기록한다.

**T8(DOI `_` 보호)은 불필요했다.** 착수 전 확인에서 markdown-it이 CommonMark를 따라 단어
내부 `_`를 강조로 보지 않음을 확인했다 — `s15327809jls0303_3`은 그대로 나오고 `_진짜강조_`만
`<em>`이 된다. 이 방어는 자작 렌더러를 전제했을 때의 위험이었고 라이브러리 선택으로 사라졌다.
방어 코드는 넣지 않았고 회귀 테스트만 남겼다.

**마크다운 문법 화이트리스트도 넣지 않았다.** 코드펜스·중첩목록·이미지·`###`은 markdown-it이
정상 렌더하므로 빌드를 막을 이유가 없다. 원시 HTML은 `html: false`로 이스케이프된다.

**계획에 없던 두 버그를 테스트가 잡았다.**
- `assertWikiLayout`이 네 하위 디렉터리의 존재를 가정했다. 개념 페이지가 없는 위키도 정당하다
- 그래프 컴포넌트 패킹이 컴포넌트마다 배율을 따로 정해, 큰 덩어리가 폭을 다 먹고 2인 섬이
  캔버스 밖으로 밀려났다. 전체가 들어가도록 배율을 한 번에 정하도록 고쳤다

**검증 결과**: 각주 출처 링크 509 → 509(손실 0), 각주 참조 1,880 → 되돌아가기 1,880,
인용 행 369(= 509 − 자기인용 140), 내부 링크 깨짐 0, 테스트 77/77, 빌드 145ms.
