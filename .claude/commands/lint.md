## 기계 검사

```bash
npm run lint:strict
```

위반이 나오면 **규칙별로 묶어** 보고한다. 규칙 번호와 뜻은 다음과 같다.

| # | 규칙 | 흔한 원인 |
|---|---|---|
| 1 | 프론트매터 필수 필드 | 새 페이지에서 `confidence`·`slug` 누락, `source`에 `confidence`를 둠 |
| 2 | 각주 참조에 정의가 있음 | 정의 블록에 넣는 것을 잊음 |
| 3 | 각주 id가 `sources.json`에 실재 | 출처를 지어냄 — **가장 심각하다** |
| 4 | 프론트매터 `sources` ≡ 본문 각주 | 각주만 추가하고 프론트매터를 안 고침 |
| 5 | wikilink가 해석됨 | 없는 개념 페이지를 링크함 |
| 6 | `##` 섹션마다 각주 ≥ 1 | 근거 없이 서술함 |
| 7 | `index.md`에서 도달 가능 | 새 페이지를 색인에 안 넣음 |
| 8 | `confidence` = 섹션 최약 근거 계산값 | 근거를 바꾸고 프론트매터를 안 고침 — `npm run sync:confidence`로 맞춘다 |

**규칙 3 위반은 즉시 보고한다.** 존재하지 않는 출처를 인용했다는 뜻이므로
다른 위반과 같은 무게로 다루지 않는다.

## 기계가 못 잡는 것 — 표본 검토

lint는 형식 무결성만 본다. 아래는 사람이 봐야 한다.

- **귀속 정확성** — 이 각주가 이 주장의 근거가 맞는가. A의 주장에 B의 논문이 달려 있지 않은가
- **티어 오분류** — 피어리뷰 논문을 C로, 백과사전을 A로 넣지 않았는가
- **`[근거없음]` 회피** — 근거가 없는 자리를 그럴듯한 문장으로 메우지 않았는가

최근에 바뀐 페이지 3개를 무작위로 골라 위 세 가지를 확인하고 결과를 보고한다.

```bash
git diff --name-only HEAD~1 -- wiki/ | shuf | head -3
```
