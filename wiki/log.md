## 2026-08-15 — 답변 게이트 도입

lint 8규칙은 `wiki/`의 정적 코퍼스만 검사한다. 그런데 이 시스템의 산출물은 `/ask`·`/debate`가 런타임에 생성한 답변이고, 답변은 저장되지도 검사되지도 않았다. `[근거]`·`[적용]`·`[근거없음]` 세 마커는 `scripts/` 전체에서 `gen-agents.mjs`에만 등장했다 — 에이전트 프롬프트를 찍어낼 때뿐이고 `lint-wiki.mjs`는 이 문자열을 몰랐다. 근거 DB만 감사받고 그 DB로 한 말은 감사받지 않는 비대칭을 없앴다.

답변을 `answers/`에 원문 그대로 저장하고 11규칙으로 검사한다. 위치가 `wiki/` 밖인 이유는 안에 두면 `lintWiki`가 답변까지 검사해 규칙 1(`type`이 `PAGE_TYPES`에 없음)과 규칙 7(색인에서 도달 불가)이 깨지기 때문이다.

검사는 위조급 7개와 형식급 4개로 갈린다. 위조급은 런타임에 해당 위인을 1회 재호출하고, 재시도 후에도 남으면 위반을 명시한 채 출력한다 — 감추지 않는다. 형식급은 기록만 하고 답변을 바꾸지 않는다. `lint-wiki.mjs`가 규칙 6·7을 기본 모드에서 경고로 낮추는 것과 같은 구조다.

핵심은 규칙 3(인용 범위)이다. 설계 결정 ②(위인 격리) 때문에 각 위인이 인용해도 되는 출처 집합이 자기 페이지 프론트매터 `sources`로 확정되어 있어, 가녜의 답변에 메이어의 전기가 나오면 위조로 판정할 수 있다. 인용 가능 집합이 열려 있는 일반 RAG에서는 성립하지 않는 검사다. 규칙 7(사회자 섹션 각주 금지)은 커맨드 문서의 "위인 발언을 요약하지 않는다" 금지가 처음으로 기계 검사를 받게 된 것이다.

런타임 검사는 오케스트레이터의 준수에 의존한다. `npm run lint:answers`가 `answers/` 전수를 다시 검사해 CI 게이트 2로 들어가며, 저장된 `check:` 블록을 읽지 않고 본문에서 다시 계산한다 — 기록을 위조해도 게이트는 속지 않는다.

구현 검토에서 구멍 하나가 잡혔다. 화자 분리기가 첫 `## ` 이전의 줄을 버리기 때문에, 서두에 위조 각주를 단 문단을 숨기면 어떤 규칙에도 걸리지 않고 통과했다. 규칙 6을 넓혀 화자 섹션 앞의 본문 자체를 위조급으로 판정한다 — 귀속되지 않은 본문은 검사할 수 없는 본문이다.

Claude Code 훅 방식(Stop 이벤트에서 트랜스크립트 검사)은 채택하지 않았다. 모델이 우회할 수 없다는 장점이 있으나 검증 장치가 세션 설정에 살아 저장소만 클론하면 돌지 않는다. 커밋 게이트가 사후에 반드시 잡는 쪽을 골랐다.

**이 게이트도 귀속 정확성은 못 잡는다.** 규칙 3은 "가녜가 인용해도 되는 출처"까지만 본다. 그리고 마커 검사(규칙 9~11)는 인용문·목록·표를 제외하므로 주장을 목록으로 늘어놓으면 마커 없이 통과한다. 오탐을 줄이려고 감수한 구멍이며 그래서 이 세 규칙은 형식급이다.

`answers/`에 예시 답변은 커밋하지 않았다. 예시를 만들려면 실제 위인 에이전트를 돌리지 않고 발언을 지어내야 하는데, 그건 이 프로젝트가 금지하는 행위다. 첫 답변은 실제 `/ask`가 만든다. 검증은 실제 위키와 `sources.json`에 대고 임시 파일로 했으며, 심어 둔 위반 6건(규칙 2·3·4·7·9·11)을 전부 탐지했다.

설계 명세는 `docs/superpowers/specs/2026-08-15-answer-gate-design.md`에 있다.

## 2026-08-15 — confidence 재정의

`confidence`가 변별하지 않았다. 위인 36명과 대립축 34건이 전원 `high`였다. 필드가 상수면 정보량은 0이다.

원인은 순환이었다. `import-pantheon.mts`의 `confidenceOf()`가 "A·B 티어가 하나라도 있으면 high"로 값을 계산했고, lint 규칙 8이 **같은 술어로** 그 값을 검증했다. 자기가 만든 값을 자기가 확인하니 원리상 실패할 수 없었다. 위인 페이지는 자기 대표 저작(tier A)을 반드시 인용하므로 술어가 항상 참이었다. 출처 페이지 140건의 `high` 125 / `low` 15도 판단이 아니라 그 출처 tier의 재진술이었다 — 출처 페이지는 자기 자신만 인용하기 때문이다.

페이지의 `confidence`를 **모든 `##` 섹션의 "그 섹션 최강 티어" 중 가장 약한 것**으로 재정의했다. 페이지 전체를 한 덩어리로 보면 언제나 high가 되지만, 섹션 단위로 보면 "연표만 2차 문헌으로 받쳐져 있다"가 드러난다. 매핑은 A → high · B → medium · C → low다.

결과: 위인 14 high / 22 medium, 대립축 27 high / 7 medium, 개념 3 high. `source` 페이지 140건에서는 필드를 제거했다.

규칙 8을 "선언값 == 계산값"으로 바꿨다. 처음으로 실패할 수 있는 규칙이 되었으며, 규칙 4(`sources` ≡ 본문 각주)와 같은 구조다. 계산은 `scripts/confidence.mjs`의 `computeConfidence()` 하나가 담당하고 lint와 `npm run sync:confidence`가 같은 함수를 쓴다 — 검증과 갱신이 어긋날 수 없다.

## 2026-08-15 — 개념 후보 탐지와 승격 3건

`concepts/`가 3개에서 자라지 않았다. 원인이 둘이었다.

첫 실행에서 이 판단이 값을 했다. 승격한 3건 중 가장 확실한 `설계연구↔설계실험`이 약한 단에 있었다 — 편집거리 0.5라 강한 단에 들지 못했다. 약한 단을 버렸다면 놓쳤을 것이다.

승격 3건은 `curator` 서브에이전트 셋이 병렬로 썼다(`CLAUDE.md`의 쓰기 권한 규칙). 근거는 전부 기존 위인 페이지의 서술과 각주에서 가져왔고 새 출처는 등재하지 않았다.

- `criterion-referenced-assessment` — 글레이저 `준거참조평가` + 메이거 `준거지향 평가`. 같은 개념의 다른 번역어

- `design-research` — 콜린스 `설계연구` + 앤 브라운 `설계실험`. 1992년 같은 저널의 창립 논문 두 편. 어느 이름이 정본인지는 문헌에 근거가 없어 판정하지 않았다

**관찰 — 규칙 8이 내용을 움직였다.** 준거참조평가를 쓴 curator가 `## 상태` 각주에 `mager-1962`(tier A)를 넣은 이유를 이렇게 보고했다: 글레이저 출처가 모두 tier B라 첫 위인 각주만 달면 `medium`으로 계산돼 `high` 선언과 충돌한다는 것이다. 문장 자체는 두 위인을 다루므로 방어되지만, 파생값을 손으로 선언하게 두면 저자가 값에 맞추려 각주를 조정한다. `CLAUDE.md`에 "선언값에 맞추려고 각주를 고치지 마라. 값을 아무렇게나 두고 `sync:confidence`를 돌린 뒤 나온 값을 받아들인다"를 명시했다.

`sync:confidence` 결과 갱신 0건 — 세 페이지 모두 선언값과 계산값이 일치했다. `wiki/index.md`의 개념 절을 3 → 6으로 갱신했다.

## 2026-08-15 — 2차 외부 검수와 결함 6건 수정

1차 검수가 콘텐츠 필터로 중단돼 `concept-candidates.mjs`와 `sync-confidence.mjs`가 검토를 받지 못했다. 프롬프트를 "우회 방법을 찾아라"에서 "비정상 입력에서 정확한가"로 바꾸고 범위를 두 파일로 좁혀 다시 돌렸다. 이번에는 완주해 8건을 지적했다.

검수자가 스스로 밝힌 한계가 있다 — 읽기 전용 샌드박스가 임시 디렉터리 생성을 막아 파일 기반 테스트 9건이 돌지 않았고, 재현은 메모리에 재구현한 로직으로 했다는 것이다. 그래서 지적을 전부 실제 코드에 대고 다시 재현했고, 확인된 것만 고쳤다.

**1. 블록 스칼라 안의 `---`를 프론트매터 끝으로 오인했다 (중대).** `editFrontmatter()`가 종료 구분자를 찾을 때 `trim()`으로 들여쓰기를 지우고 비교해, `|` 블록 스칼라 값 안의 `  ---`을 끝으로 읽었다. 실제 재현에서 `confidence: medium`이 값 한가운데(`alpha` 다음)에 삽입되고 원래 `confidence: high`는 그대로 남아 YAML이 깨졌다. 구분자를 들여쓰기 없는 줄 전체 일치로 바꿨다.

**2. 유니코드 정규화가 없었다 (중대).** `norm()`이 NFC/NFD와 전각/반각을 다루지 않아 눈에 같은 글자가 다른 개념이 됐고, NFD 문자열은 코드포인트가 늘어나 `주의`(2자)가 4자가 되면서 3자 하한을 통과해 `민주주의와 교육`에 포함으로 잡혔다. `CLAUDE.md`가 개념 파일명 규칙에서 다루는 바로 그 문제다. NFKC 정규화를 앞에 걸었다.

**3. 값이 빈 `confidence:`를 교체하지 못했다 (경미).** 정규식이 콜론 뒤 공백을 요구해, 근거 페이지에 `confidence:`와 `confidence: medium` 두 줄이 생겼다.

**4. `concepts` 타입 검증이 없었다 (경미).** 값이 문자열이면 글자별로 순회돼 `인 ↔ 인지` 같은 가짜 후보가 나왔고, 숫자면 실행 전체가 예외로 멈췄다. 배열·문자열만 받도록 막았다.

**5. 접두사 분기가 도달할 수 없는 죽은 코드였다 (경미).** 공통 접두사가 절반 이상이면 편집거리 비율은 반드시 0.5 이하라 앞선 약한 편집거리 분기가 항상 먼저 반환한다. 분기를 지우고 테스트 이름도 실제 판정에 맞게 고쳤다. 비율 표시는 소수 셋째 자리로 늘렸다 — 둘째 자리로 자르면 임계값을 넘은 0.34375가 통과한 0.34와 같아 보인다.

**6. 편집하지 못한 파일을 성공으로 집계했다 (경미).** 반환값을 확인하기 전에 `updated`·`removed`에 기록했다. `skipped` 목록을 추가하고 편집 성공을 확인한 뒤에만 집계한다.

**검수가 못 본 결함이 하나 더 나왔다 — CRLF 파일에서 `sections()`가 빈 배열을 냈다.** 검수는 CRLF를 `sync-confidence`의 줄바꿈 혼합(경미)으로만 봤는데, CRLF 회귀 테스트를 쓰다가 더 큰 것이 드러났다. JS 정규식에서 `\r`은 줄 종결자라 `(.+)$`가 `## 제목\r`을 잡지 못한다. 그래서 CRLF 위키 파일은 섹션이 통째로 사라져 lint 규칙 6이 그냥 통과하고, `computeConfidence()`가 `null`을 돌려줘 규칙 8도 건너뛴다. `wiki-parse.mjs`와 `check-answer.mjs`의 줄 분리를 `/\r?\n/`로 바꿔 고쳤다.

검수의 지적 중 **8번(테스트가 보존 계약과 실패 입력을 검증하지 않는다)은 타당했다.** 위 항목마다 회귀 테스트를 추가해 141개에서 150개가 되었다. 실제 위키와 답변은 영향이 없다(lint 오류 0, `sync:confidence` 갱신 0·건너뜀 0, 답변 위조급 0, 개념 강한 후보 12건 그대로).

검수가 "문제없다"고 확인한 것: 본문의 수평선·코드블록 안 `---`, 들여쓴 `check.confidence`와 `confidence_note:` 같은 유사 키, BOM, 파일 끝 개행 없음, `levenshtein()`의 경계값, `4C/ID`·`Knowledge Building` 같은 영문 개념. 현재 `concepts` 144개는 모두 문자열이며 NFC 상태였다 — 2번은 잠재 결함이었지 현행 데이터의 오류는 아니었다.
