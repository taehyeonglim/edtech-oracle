# 답변 기록

`/ask`·`/debate`가 생성한 답변을 그대로 보관한다. 요약하지 않는다.

`npm run lint:answers`가 이 디렉터리를 전수 검사하고 CI 게이트 2로 들어간다.
**위조급 위반이 있는 답변은 저장소에 들어올 수 없다.**

`type: answer`가 아닌 파일(이 README 포함)은 검사에서 건너뛴다.

## 형식

```markdown
---
type: answer
command: ask                    # ask | debate
question: "LMS를 새로 설계한다면 무엇부터 보나"
asked: 2026-08-15
speakers: [robert-gagne, richard-mayer]
---

## robert-gagne

[근거] 학습 결과의 종류에 따라 필요한 조건이 달라진다.[^gagne-1965]

[^gagne-1965]: Robert M. Gagné. (1965). The Conditions of Learning.
    Holt, Rinehart and Winston. — tier A · [[sources/gagne-1965]]

## _orchestrator

이 둘은 설계의 출발점에서 갈린다.
```

- `## <slug>`가 화자 구분자다. `/debate`는 같은 slug이 라운드마다 반복 등장하며 문서 순서가 라운드 순서다
- `_orchestrator`는 예약 화자다. **각주를 쓸 수 없다** — 사회자가 각주를 달면 그건 위인 발언의 합성이다
- 프론트매터 `check:` 블록은 사람이 읽기 위한 기록이다. 게이트는 이 값을 믿지 않고 본문에서 다시 계산한다

## 검사 규칙

| # | 규칙 | 심각도 |
|---|---|---|
| 1 | 각주 참조에 정의가 있다 | 위조급 |
| 2 | 각주 id가 `sources.json`에 실재한다 | 위조급 |
| 3 | 각주 id가 화자 페이지의 `sources` 안에 있다 | 위조급 |
| 4 | 각주의 tier 표기가 `sources.json`과 일치한다 | 위조급 |
| 5 | 화자가 실재 위인 slug이거나 `_orchestrator`다 | 위조급 |
| 6 | 프론트매터 `speakers` ≡ 본문 화자 집합 | 위조급 |
| 7 | `_orchestrator` 섹션에 각주가 없다 | 위조급 |
| 8 | 각주 정의가 `— tier X · [[sources/id]]`로 끝난다 | 형식급 |
| 9 | 주장 문단이 세 마커 중 하나로 시작한다 | 형식급 |
| 10 | `[근거]` 문단에 각주가 있다 | 형식급 |
| 11 | `[근거없음]` 문단에 각주가 없다 | 형식급 |

**위조급**은 런타임에 해당 위인을 1회 재호출하고, 커밋 게이트에서 배포를 막는다.
**형식급**은 기록만 하고 답변은 그대로 출력한다.

## 이 게이트가 못 잡는 것

- **귀속 정확성** — 규칙 3은 "가녜가 인용해도 되는 출처"까지만 본다.
  "이 각주가 이 문장의 근거가 맞는가"는 여전히 `/lint`의 표본 검토가 담당한다
- **목록으로 늘어놓은 주장** — 규칙 9~11은 인용문·목록·표를 제외한다.
  오탐을 줄이려고 감수한 구멍이며, 그래서 이 세 규칙은 형식급이다
